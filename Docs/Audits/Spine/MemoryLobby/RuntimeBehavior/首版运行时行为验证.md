## 结论与交付范围

MemoryLobby 内已建立可直接播放的独立验证场景：保留原作 Idle、背景和头发动态，增加鼠标注视、微幅头部跟随、三组随机摸头表情、Neutral Thinking 及真实音频驱动的嘴部开合。Speaking 与摸头可以同时表现，嘴部由语音独占。

最终行为检查 **25/25**、真实语音检查 **9/9** 通过；最终读取 Unity 控制台时没有 error/warning。这些结果证明当前原型的局部控制与恢复路径可用。静帧对照未见明显眼部越界、手脸分离或附件破损；实时交互手感、全部过渡画面和正式应用接入仍需分别验收，不能将逻辑检查等同于原作质量的最终认可。

本次使用 Unity 与 spine-unity 实现，源文件未修改。没有生成新 `.spine` 工程或关键帧动画，没有向 GiftCompanion 写入运行时组件，LLM action 白名单仍为 `none`。

## 直接体验

Unity 工程：`W:\Machine\VSCode\Mika_Gift\Material\Mika_MemoryLobby\MemoryLobby`。

场景：[CompanionValidation.unity](../../../../../Material/Mika_MemoryLobby/MemoryLobby/Assets/CompanionValidation/CompanionValidation.unity)。

1. 打开该场景并点击 Play，在 Game 视图内观察原作待机。
2. 鼠标在视图内移动，眼睛先跟随；停留后头部缓慢、小幅跟上。鼠标离开视图或窗口失焦后恢复自然待机。
3. 单击头部获得短反馈；按住约 0.25 秒并轻拖，进入持续摸头。松开、越过头部容差范围或失焦后退场。按住不动不会进入摸头。
4. 多次分别摸头，可随机遇到闭眼、得意或害羞。一次持续手势保持同一组，允许连续两次选中相同表情。
5. 在 Game 视图按 **F8** 打开验证面板。用 `Thinking` 查看侧看、回看和轻歪头；用两枚 `Voice` 按钮播放提供的语音。语音播放时继续摸头，观察眉眼保留、嘴部随声音开合。
6. `Pause voice` / `Resume voice`、`Mute voice`、`Stop voice` 分别验证暂停、静音和取消；`Idle` 返回待机。F8 隐藏面板。

验证面板默认隐藏，只供这次能力检查。它不代表正式应用的对话界面。当前头部命中范围只针对该大厅相机和构图校准，触摸范围可在配置中继续调整。

## 当前表现设置

### 注视和头部

底层始终播放 `Idle_01`。注视使用 `Touch_Eye_Key`，头部微调使用 `Head_Rot`；真实节点名存入角色配置。注视偏移上限为骨架坐标 `(0.48, 0.34)` 的椭圆，眼睛响应约 0.2 秒；停留约 0.55 秒后，头部约 1.05 秒缓慢跟上，最大 ±1°。无输入时叠加非常轻的视线与头部变化。

采用 `BeforeApply` 恢复上一帧局部基线、`UpdateLocal` 应用一次当前偏移，原作动画和约束照常更新。关闭局部控制即恢复原作姿态；骨架重建重新绑定节点、恢复 Idle，并解除旧摸头和语音驱动。

### 三组摸头表情

| ID | 原作来源 | 当前反馈 |
|---|---|---|
| `pat_closed_eyes` | `Pat_01_A`，0 秒 | 原作闭眼及闭嘴附件；由外部手势保持零时长姿态 |
| `pat_playful` | `Talk_01_A`，2 秒 | 原作得意眉眼及闭嘴形 |
| `pat_shy` | `Talk_03_A`，12 秒 | 原作害羞眉眼和闭嘴形，小幅侧视 |

配置提取已有附件设置，不播放完整对白片段，也不转发其声音 Event。随机池等概率抽取，允许重复；持续轻拖不重复启动或抽样。睁眼表情继续保留原作眨眼。入口与退场用原作闭眼附件遮掩离散表情切换，约 0.12 秒；释放窗口约 0.22 秒。附件本身不做不存在的中间形插值，过渡观感仍需实际体验。

### Thinking

采用 `thinking_neutral`，眉眼来源为 `Talk_03_A` 的 0.7 秒设置，嘴部使用原作自然闭嘴形。先侧向抬眼，约两秒后短暂回看，再侧看；第一轮约 7.2 秒，后续周期约 6.05～8.35 秒，回看时机和停留时长小幅变化。头部目标约 0.9°，仍受当前托腮质量要求约束。

Thinking 的动态来自注视、头部微调、原作眨眼及已有眉眼组合。首版只启用 Neutral，没有将摸头候选自动扩展成八种正式情绪。

### 语音口型

实际读取用户提供的 `Material/Mika_MemoryLobby/Audio`，找到两段 OGG，无需额外提供 WAV：

| 样本 | Unity 解码时长 | 单声道 PCM 样本数 |
|---|---:|---:|
| `CH0069_ExWeapon_Get` | 18.732 秒 | 826,081 |
| `CH0069_Gachaget` | 15.845 秒 | 698,779 |

验证副本导入设置为 `Decompress On Load`，通过 `AudioClip.GetData` 获取 PCM；按约 25 毫秒窗口缓存短时能量，使用 `AudioSource.timeSamples` 选择实际正在播放的窗口。包含噪声门、温和归一化、开闭迟滞、上升/释放平滑和最短切换间隔。

嘴部使用源插槽 `Mouse_normal_01` 的 `Mouse_normal_close` / `Mouse_normal_01` 两种现有附件。Speaking 时只有表情协调器写嘴部，摸头仍能保留兼容眉眼。暂停、完全静音时闭嘴并保留 Speaking；低但非零音量仍按 PCM 开合；取消与自然结束释放口型，恢复当前基础表情。新段替换时清除旧段并增加 generation。

这次没有逐音素数据，也没有接入 GPT-SoVITS `/tts`、实时对话队列、跨段保持 Speaking 或网络请求取消。相关接入需以正式队列的播放源与业务状态为权威，不能直接把验证面板当作语音队列使用。

## 检查结果和复现

行为结果：[smoke_report.json](smoke_report.json)。25 项通过，失败项为空。

- 固定种子 17，120 次触摸抽样覆盖三组；持续期间重复开始不新增抽样。
- 头部命中、区域外拒绝、缩放/水平镜像坐标映射、短点击、按住不动、轻拖、越界/失焦和取消通过。
- Thinking 回看和任意周期中切入 Speaking 通过；触摸结束保留当前状态；语音 Mouth 优先于摸头。
- 按 30 Hz 推进 18,000 帧，等效 600.00006 秒；检查骨骼变换有限，禁用局部控制后与同一原作 Idle 时刻的全部 743 根骨骼比较，世界 X/Y 最大差为 **0**。
- 15/60 Hz 的一秒平滑结果：注视差约 `1.49e-8`，头部角度差约 `4.17e-7` 度。这是受控目标的数值检查，不是整场性能测试。
- 重新启用控制器和重建 SkeletonAnimation 后，节点绑定、Idle 播放与交互清理正常。

**600 秒结果是主动推进的模拟时间，不代表连续十分钟的实时画面或性能验收。** 本轮没有宣称 FPS、GC 或目标机器性能预算达标。

真实语音结果：[voice_report.json](voice_report.json)。9 项通过，失败项为空。两段音频分别观测到开口/闭口帧并自然结束；其余检查覆盖暂停时间冻结、恢复位置推进、静音、低音量、替换、取消，以及独立 AudioSource 不驱动角色嘴部。帧数只说明两种嘴形均出现，不用于推算或承诺帧率。

在验证场景 Play 后，可通过菜单 `Companion Validation > Run Behavior Smoke (Play Mode)` 复现行为检查；`Run Voice Smoke (Play Mode)` 完整播放两段语音并检查生命周期，约 40 秒结束。测试会短暂接管输入、语音和原作轨道，结束后恢复待机；请分别运行，不与手动交互混用。结果写入本报告目录。

## 下一轮应优先解决

1. 用户在完整 Game 视图中体验跟随速度、头部幅度、摸头命中范围、三组表情和闭眼过渡。依据反馈先调现有参数，不增加大幅新动作。
2. 录下连续交互和 Thinking→Speaking→Idle，复核源场景各阶段的手脸支撑、眨眼、遮挡和附件切换；补不同视图宽高比与连续实时十分钟检查。
3. 补充一段轻声或含较长停顿的实际 TTS 输出，再接入真实分段播放队列，验证段间 Speaking、真实 Audio Ready、turnId 和取消令牌。
4. 再评估原作一次性动作及八种情绪的真实资源映射；逐项验证后才开放 Manifest 能力。挥手仍是未证实资源，当前不启用。
5. 正式 GiftCompanion 接入沿用 `ICompanionVisualController` 与唯一 CharacterCore，完成 Menu/MomoTalk 输入阻断和场景切换清理。当前 [项目总宪法第 49 节](../../../../../项目总宪法.md) 要求“只有 Phase 0 全部成功后才能继续”；本次独立素材验证不替代 DeepSeek、SQLite、GPT-SoVITS、3D 原动画和透明窗口等 Phase 0 验收。

## 实现位置

代码与配置集中于 Unity `Assets/CompanionValidation`：Bootstrap 仅装载原件与搭建验证环境；LocalMotion 管理平滑目标及骨骼基线；PointerInteraction 负责命中和手势；ExpressionOverlay 是附件的唯一写入者；SpeechDriver 按当前音频段驱动口型。Editor 工具只负责盘点、截图和上述真实场景检查。

它们没有新建会话、数据库、LLM/TTS 请求或第二个 CharacterCore。正式业务接入时需把验证用状态入口与播放按钮替换为应用既有状态、播放源与生命周期接口。
