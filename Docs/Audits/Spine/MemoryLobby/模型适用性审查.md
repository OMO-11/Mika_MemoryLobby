## 接入前的具体问题

### 1. Unity 导入扩展名与 Runtime 组合

本包使用通用 `.skel` 和 `.atlas`，不符合 spine-unity 的标准资源导入命名。应在正式接入副本中使用 `.skel.bytes`、`.atlas.txt` 并保留 atlas 引用的 PNG 文件名，生成对应 Atlas、材质及 SkeletonDataAsset。官方明确说明不能以 `.skel` 扩展名加载。[官方资源导入文档](https://esotericsoftware.com/spine-unity-assets)

工程固定为 **Unity 6000.6.4f1**；核查时官方兼容表把 spine-unity 4.2 列至 **6000.3**，4.3 列至 **6000.4**，均未列出本工程版本。官方同时说明 4.2 数据不能直接交给 4.3 Runtime，需要重新导出。应确认所选 4.2 Runtime 提交的支持记录并在当前工程实测；不能以浏览器解析成功宣布 Unity 兼容，也不能仅因超出文档范围断言必然失败。[官方安装和版本说明](https://esotericsoftware.com/spine-unity-installation)

交付 README 将 height 后的 `100.0` 描述为 BA “额外 float”，并建议旧运行时可裁掉 4 字节。本次实际读取该字段为 **referenceScale=100**；官方 4.2 分支 C# 解析器也在 height 后读取 referenceScale。因此不能据此认定当前数据存在私有头部损坏，**不要未经验证删除这 4 字节**。旧版本失败的具体根因未在本次复现；npm 补丁号也不能直接当作 spine-unity 版本号。[官方 4.2 SkeletonBinary 源码](https://github.com/EsotericSoftware/spine-runtimes/blob/4.2/spine-csharp/src/SkeletonBinary.cs)

### 2. 对话动画不是已适配任意 TTS 的 Speaking

实际时间线显示，两套 `Talk_01_A` 都只有 AttachmentTimeline，而 `Talk_01_M` 包含身体变换和 Event，CH0294 还包含 Physics mix 时间线。它们应按实测结果组织轨道；README 把 A/M 标为“女声/男声”的语义不能直接采用。这些片段有约 15～35 秒的固定节奏，尚未证明可跟随任意 GPT-SoVITS 语音时长。

CH0294 的 `Talk_01_M` 在约 0.667 秒和 5.5 秒实际发出原作 `Sound/...` 与 `Talk` Event；CH0069 的对应片段也发出 `Talk` Event。实时生成对话时需明确处理 Event，避免沿用原作声音触发规则而与 TTS 冲突。Event 本身不说明本包带有可播放原录音。

需要验证 Idle 与对白轨道叠加、表情保持、语音结束停止 Speaking、用户打断和返回 Idle，再登记动作白名单。Dev_*、Dummy 不应默认开放给 LLM。

### 3. Thinking、情绪和触摸仍需正式映射

手册允许 Happy/Concern Thinking 暂时统一回退 Neutral Thinking，也允许缺失动作回 Idle，但没有证据表明当前已有经验证的 Thinking 表现。应从实际姿态选取或制作 Neutral Thinking，再定义八种情绪的实际映射与回退。无显式命名不等于模型无法表现该情绪。

CH0069 的 Pat_01_A、Pat_01_M、Look_01_M 为零时长姿态片段，解析正常，不应判为损坏。触摸控制器需支持姿态保持、对应 End 片段及返回 Idle。没有 BoundingBox 附件不妨碍按骨骼或屏幕区域建立 HitArea。

### 4. 当前交付预览图不能直接作为成品画面

人工查看 CH0069 的 Idle_01 @0.5 秒、CH0294 的 Idle_01 @0.5/6 秒：主要角色和场景可辨，但两者都有可见的细三角接缝；CH0294 画布外围存在大片透明区和不规则场景边缘。需要在 Unity 设置相机、缩放和裁切，验证是否能在目标窗口比例持续覆盖显示区域。

这些现象出现在 Canvas 交付图，尚不能归因为骨骼损坏，也不能证明 Unity 会出现同样问题。背景/角色划分仍是名称启发式，背景平面图不是恢复原大厅动态的替代品。应优先保留整体骨骼，验证 additive 混合、透明边缘和 CH0294 的 37 个 Physics 约束。

8 页 atlas 均未声明 PMA，按包说明以 straight alpha 为导入起点，仍需核对实际透明边缘。spine-unity 4.2 默认使用 PMA 工作流，须显式匹配纹理与材质设置。[官方 Alpha 导入说明](https://esotericsoftware.com/spine-unity-assets#Premultiplied-vs-Straight-Alpha-Import)

### 5. 授权核验应按手册登记

手册第 12 节明确要求 Runtime 集成和最终分发前核验许可证。目前没有找到本包对应核验记录。模型来源、Runtime 授权与素材使用范围应分别记录；README 的“学习用途”描述不代替许可证明。[官方 Runtime 许可](https://esotericsoftware.com/spine-runtimes-license)

## 下一阶段验收顺序

1. 核验授权与固定 Runtime 提交，在正式资产副本中整理 Unity 扩展名。
2. 在 Unity 6000.6.4f1 中导入一个模型，播放完整 Idle 循环，验证透明材质、场景裁切及窗口缩放，记录帧耗时和加载占用。
3. 核验 Talk 轨道及事件、Pat/Look 和 Physics，选择 Neutral Thinking，定义情绪、动作白名单、HitArea 与回退。
4. 用控制器验证 Thinking → Speaking → Idle、Touched → Idle、打断与回退。此后再判定该模型是否通过 Companion 接入验收。

作为工程验证顺序，可以先测 **CH0069_home**：它不含 Physics 约束，交付画布背景覆盖也更完整，首轮需要排查的变量较少；它的骨骼更多，不能据此保证性能更好。CH0294 仍是有效候选，应额外验证 Physics 与显示裁切。
