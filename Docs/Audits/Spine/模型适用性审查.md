## 接入前需要处理的重点

**1. 先补齐真实资源包。** 每个模型至少需要骨骼数据、atlas 和 atlas 实际引用的全部纹理页。现有 JSON 共记录 8 页纹理，但这些 PNG 在指定目录均不存在。`.spine` 编辑工程不是运行时播放的必需条件；若需要制作新的 Thinking 或表情动作，拥有可编辑源工程会更便于制作。先核对资源校验和，再重新解析与导入，不应把元数据当成模型资产。

**2. 固定并实测 Spine 版本组合。** 本地 npm 运行时为 4.2.120；元数据记录导出头为 4.2.33。`export_manifest.mjs` 声称新版 4.2 解析成功、旧版和 4.3 解析失败，并写有二进制头差异说明。这是既有脚本中的声明，本次没有源文件复现；不能将 npm 的 4.2.120 补丁号直接当作 spine-unity 的版本要求。

官方说明 Spine 4.2 或更早的数据不能直接由 spine-unity 4.3 读取，升级 4.3 需要重新导出。当前安装文档的兼容表将 spine-unity 4.2 列为支持 Unity 至 6000.3，而本工程固定为 6000.6.4f1；这个组合超出了页面列明的范围，需核对具体 Runtime 提交的支持记录并实测，不能直接宣称兼容，也不能据此断言必然失败。[官方安装与版本说明](https://esotericsoftware.com/spine-unity-installation)

**3. 验证可复用动作，补齐状态与情绪映射。** Idle_01 是待机候选，Talk、Pat、Look 是行为候选。不能仅凭 A/M 后缀决定脸部、身体轨道的用途，也不能把某段固定对白动作直接认定为适用于任意 GPT-SoVITS 语音。需实测轨道叠加、时长控制、动画结束、打断及回 Idle；审查原 Event/音频处理，避免生成对话时意外触发原录音。

手册没有要求每个状态必须对应一段独立动画；MomoTalk、Menu 等可由控制器处理。现有列表无 Think 或八种情绪的显式命名，也不证明骨骼完全无法做这些表情，只说明目前没有可核验的正式映射。第 14 节允许三类 Thinking 暂时合并为 Neutral Thinking；第 12 节允许缺失动作回 Idle。Idle 回退是缺项保护，不能据此证明第 50 节的 Thinking 动画要求已经完成。

CH0069 的 Pat_01_A、Pat_01_M、Look_01_M 记录为零时长但有时间轴，可能是静态姿势片段，不应直接判为损坏；应验证姿势保持与对应 End 动作。Dev_*、Dummy 等不应未经人工验证就进入 LLM 动作白名单。正式配置需给八种情绪定义映射或明确回退策略，并保证未知动作回退不会抛异常。

**4. 保留场景效果并验证触摸。** 背景分类使用名称正则，不是人工确认的图层定义。例如 CH0069 的 `L_Index_02_light` 也被规则分为背景，可能涉及手部光效，不能盲目按该表拆除或展平。两模型都记录了 additive 插槽；CH0294 还有 37 个 Physics 约束，需检查 Unity 中的材质混合、透明边缘、发丝/衣物动态、窗口缩放和画面裁切。HitArea 可按实际骨骼位置建立，不能因元数据没记录 BoundingBox 就断言无法实现触摸。

贴图尺寸按 RGBA32、无 mipmap 估算分别为 64 MiB 与 48 MiB；这是像素数据量估算，不是实际 Unity 显存或性能测试。手册没有具体骨骼数/贴图尺寸上限，不能仅凭资源规模判不合格。最终需在目标 Windows 工程查看帧耗时、Draw Call 和加载占用。

**5. 将工具声明与实测证据分开。** `export_manifest.mjs` 的 `playbackVerified.results` 直接写入 `parsed: true` 与 `distinctFramesConfirmed: true`，没有在该脚本执行真实播放检查；不能用于自动验收。`inspect_spine.mjs` 的 `missingRegions` 统计 `!r.page.texture`，而该脚本未加载纹理，不能据其值判断 atlas 区域或 PNG 缺失。当前浏览器播放器只能视为验证工具，不能替代手册要求的 spine-unity 接入。

## 建议的验收顺序

1. 补齐真实骨骼、atlas、全部引用纹理，登记来源与手册要求的授权核验记录。
2. 在固定 Unity 版本中确认 Runtime 组合，重新解析并播放一个模型的 Idle_01，完成 Phase 0 的 Spine 子项。
3. 实测 Talk、Pat、Look、场景效果与物理约束，再填写实际 Manifest、情绪映射与触摸区域。
4. 验证 Thinking、Speaking、Touched、取消和回 Idle，记录 Unity 播放与性能结果后再作接入验收。

本次仅新增审查报告与结构检查证据，没有修改原始素材、导出工具或 Unity 工程。现阶段适合保留两者为候选，无法依据现有证据认定其中某一模型已经满足项目标准或性能优于另一模型。
