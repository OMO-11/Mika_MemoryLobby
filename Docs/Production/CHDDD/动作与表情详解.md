# CHDDD 动作与表情详解

冻结日期：2026-10-11。搭配[主程序资源接入清单](主程序资源接入清单.md)和[机器清单](../../../Material/CHDDD/Integration/resource_manifest_v1.json)使用。以下描述最新 Blender V17 中保留的表现；Unity V7 缺少后续 Success / HeadClick 修订和两个新表情，不能按此描述宣称整包一致。

## 1. 表现层级与共同约束

日常微动作维持轻呼吸、重心和自然视线，服务长期陪伴。情绪回应通过全身关键姿态、停留与快慢节奏让缩小后的桌宠仍可理解。欢迎、突然受惊等特殊演出可以更明显，但低频触发；不把每次说话或状态更新都变成演出。

完整动作在 Blender 制作，发梢、裙摆、披肩、翅膀的跟随以骨骼曲线烘焙。它们随当前动作时间播放，不是 Unity 的实时风、碰撞或任意加速度模拟；拖动窗口再快也不会自动重算布料。后续 Procedural Rig 只做微调，避免重复叠加整套发衣摆动。

所有方案无持枪动作。光环随 Head，保持已调整的较高位置。闭眼使用眼睑 / 皮肤形变覆盖眼眶，**不得通过缩小瞳孔表达困倦、生气或惊讶**。身体动作负责 Head，V2 Emotion Mask 排除 Head，避免模板覆盖歪头和受惊演技。

## 2. 七个循环动作

| 动作 | 身体表现 | 动作内表情过程 | 宿主使用方式 |
| --- | --- | --- | --- |
| Idle · 4.0 秒 | 原 Café 待机基础，轻呼吸、重心微调，发衣保持自然弱动态 | neutral 基调与短眨眼，嘴部放松 | 无其他事件时循环，不用频繁重播第 1 帧 |
| Walk · 1.333 秒 | 原 Café 行走，保留日常步态和来源发衣，原地循环 | neutral / 自然眨眼，避免行走不断换模板 | 只有宿主移动时播放；位移、方向和停止由宿主控制 |
| Thinking · 4.8 秒 | 轻托下巴，头肩与视线配合，低强度思考，发衣延迟稳定 | 思考与关切、眨眼和嘴型轻变，避免长时间冻结一张脸 | 等待 LLM / 解析时循环；素材中没有三条独立的 Neutral / Concern / Happy Thinking 全身 Clip |
| Working · 3.6 秒 | 稍前倾专注，小幅规律手部动作，不依赖额外桌子键盘 | 专注的轻微眼眉和嘴型变化 | 工具执行中循环，不表示实际键盘输入或操作系统动作 |
| HeadPat · 4.6 秒 | 低头放松，肩部松开，身体柔和摇摆，长发和衣服跟随 | 接受触摸 → 舒服 / 开心 → 放松，伴随柔和眨眼 | Enter → Loop；长按释放走 Exit；真实拖动立即抢占 |
| Dragging · 11.233 秒 | 原游戏举起动作，第 29 条 `CH0069_Formation_Pickup`；保留主体与来源发衣，边界做速度接缝整理 | 专属举起表情，去掉来源危险眼部缩放；不直接复用原缩瞳动画 | Enter → Loop；释放走 Exit。窗口移动与鼠标锚点由宿主负责 |
| Sleep · 6.0 秒 | 原地打盹，低头慢呼吸，发衣微动 | 真实闭眼、柔和困倦眉，嘴部放松；区别于仅设置 sleepy 预设 | Enter → Loop；唤醒走 Exit，不自动替主程序计算精力 |

循环的 30 FPS 帧范围分别为 Idle 1–121、Walk 1–41、Thinking 1–145、Working 1–109、HeadPat 1–139、Dragging 1–338、Sleep 1–181。首末端点按 `(末帧 - 首帧) / 30` 计时，不能把 121 个采样误写为 121/30 秒。

## 3. 五个短反馈动作

### Wave · 3.6 秒

先收身准备，再探身抬单手问候，两次清楚的招手；头肩和另一只手呼应，双翼在挥手中轻扇，翼根与羽片有先后。最后一次挥手直接接上收手，收势不额外顿住。长发、披肩和裙摆随上身运动，较主体稍晚收稳。

脸部顺序为注意用户 → 明快微笑 → 短眨眼 → 放松收势。用于回来问候等低频事件，不作为常驻待机或每条消息的统一开场。完整单次后回 Idle；当前默认淡入 0.18 秒。

### Success / 用户别名 succeed · 3.4 秒

先收手和轻下沉蓄势，再挺胸踮脚，双手向头顶斜上方展开成 **Y 形**，保留明确欢呼姿态，再缓冲落回。身体和脚部幅度沿用用户接受的版本，强化点在轮廓、节奏和情绪。披肩侧片随抬臂让位，落臂后收回；现有修正不等同于实时布料碰撞。

脸部由专注起势进入欢呼，**手臂起举阶段就迅速闭眼**，约 0.65–0.67 秒完全闭合，上弧笑眉表达喜悦；保持后再自然恢复。上弧使用 `Pet_BrowHappy_Review`，不是 sad / sleepy 的下垂眉。后续 V9 提前闭眼时序保留于 V17。

工具成功或明确夸奖事件触发，单次后回 Idle；默认淡入 0.18 秒。**Unity V7 仍是较早的举手形态和闭眼时机，新增笑眉也不在 V7 五形变控制器的写入列表。** 正式呈现此版需完整同步。

### Confused · 3.4 秒

先停下并稍后缩，身体、肩颈和另一只手参与反应；头明显倾斜约 23°，一只手移到头侧，掌心朝自己，手指轻弯并轻挠两次。关键头 / 躯干姿态有约 0.6 秒的可读停留，挠头手可继续活动；之后连续收手与恢复，发梢稍晚跟上。

脸部顺序为疑问 → 略担心 → 缓和，眼眉嘴与身体时间共用。素材的 `emotion: confused` 是默认意图标签，不表示运行时整段直接套静态 confused 表情。作为工具失败或疑惑回应使用，单次后回 Idle；默认淡入 0.28 秒。

### HeadClick · 1.8 秒

头部被突然短点后，迅速缩身 / 后撤，**双手护住头顶两侧**；先以闭眼和图集 200 的三角嘴形成 `-A-` 受惊感，随后放下手，抿嘴、皱眉佯装生气。认出用户的缓和段也不转笑嘴，保持亲近的假生气，不演成持续敌意。发衣随受惊后撤并延迟收稳。

默认淡入 0.10 秒，短促反应后回 Idle。Unity V7 已有闭眼三角嘴和后段佯怒，但双手护头是 V8 后续身体修订，仍需同步。一次短点只启动一次；长按与拖动不应另外补触发短点。

### BodyClick · 2.6 秒

先收肩蜷身、双手靠胸，脚尖内扣，身体后缩；姿态保留约半秒，让小尺寸下也能看出害羞和被突然碰到的反应。视线移开后短暂回望，末尾后缩时双翼轻抖并渐稳，再恢复。

脸部顺序为触碰惊觉 → 害羞 / 移开视线 → 短暂回望 → 放松。默认淡入 0.12 秒，单次后回 Idle。不要用同一套 HeadClick 的佯怒过程覆盖它。

## 4. 六个进入 / 退出片段

| 片段 | 秒 / 30 FPS 帧 | 职责 | 固定后继 |
| --- | --- | --- | --- |
| HeadPat_Enter | 0.9 / 1–28 | 普通姿态进入接受摸头，脸部同步放松 | HeadPat |
| HeadPat_Exit | 1.1 / 1–34 | 收回低头与摇摆，缓和恢复 | Idle |
| Dragging_Enter | 0.7 / 1–22 | 从地面状态进入被举起的姿态，含短暂惊觉 | Dragging |
| Dragging_Exit | 0.9 / 1–28 | 从举起姿态缓冲放下，发衣收稳 | Idle |
| Sleep_Enter | 2.2 / 1–67 | 掩嘴呵欠、低头、渐闭眼进入打盹 | Sleep |
| Sleep_Exit | 1.8 / 1–55 | 唤醒、恢复站姿与睁眼 | Idle |

它们全部不循环，各有同名 `PetV2_FaceProcess_*`、`PetV2_Shapes_*` 和 `PetV2_Mouth_*`。对外始终按所属逻辑动作调用；尚未进入循环就释放，也需要中断当前 Enter 并进入相应 Exit。当前底层 `CurrentAction` 不区分 Enter / Loop / Exit，宿主判断精确阶段应查看 Animator 的实际状态。

## 5. 九个基础表情

基础表情是可保持的脸部预设，不是九个全身演出。V2 Clip 统一为 `PetV2_FaceStatic_<首字母大写名称>`，手动切换默认 0.5 秒 Smoothstep，支持从当前权重中途接续；全部 EyeWide 为 0。

| ID | 意图 | 嘴型 | Blink | BrowSad | BrowAnnoyed | BrowSleepy | 共享枚举 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| neutral | 放松基准 | 300 | 0 | 0 | 0 | 0 | 是 |
| happy | 日常开心 | 706 | 0.10 | 0 | 0 | 0 | 是 |
| shy | 害羞 | 705 | 0.15 | 0 | 0 | 0 | 是 |
| concern | 关切 / 担心 | 604 | 0.10 | 0.55 | 0 | 0 | 是 |
| sad | 难过，眉头上扬、眉尾下垂 | 604 | 0.18 | 1 | 0 | 0 | 是 |
| surprised | 吃惊，嘴张开，保留眼球尺寸 | 605 | 0 | 0 | 0 | 0 | 是 |
| annoyed | 不满，眉头下压、半闭眼 | 305 | 0.42 | 0 | 1 | 0 | 是 |
| sleepy | 困倦，完整闭眼、柔和弧眉 | 305 | 1 | 0 | 0 | 1 | 是 |
| confused | 内部疑惑素材 | 401 | 0.08 | 0 | 0 | 0 | 否；业务可用 concern + Confused 动作 |

表中形变权重为 **0–1**，Unity `SetBlendShapeWeight` 使用 **0–100**。眉形还包含面部骨骼通道，不能仅按表中数字复制而丢弃 Face Clip。9 个静态表情 Clip 各为约 2 秒保持，不要按 2 秒后自动退出情绪。

保留的 8 组 Neutral 过渡为 Happy / Shy / Concern / Sad / Surprised / Annoyed / Sleepy / Confused，均为 1–16 帧，即 0.5 秒，包含 `Pet_Transition_NeutralTo*`、`Pet_TransitionShapes_NeutralTo*`、`Pet_TransitionMouth_NeutralTo*`。它们是旧恢复方案的示例，不在当前 V2 45 个 Clip 中。正式 V2 可在任意两种基础情绪间从当前状态插值，不必先退 Neutral。

## 6. 动作专属表情数据

每条身体动作对应四个制作数据项：身体 `PetV2_<Name>`、面部骨骼 `PetV2_FaceProcess_<Name>`、形变 `PetV2_Shapes_<Name>`、嘴型 `PetV2_Mouth_<Name>`。前两者进入 Unity 动画；后两类眼眉 / 嘴型变化通过 `action_face_profiles_v2.json` 的逐帧 samples 驱动。静态 `emotion` 字段仅标记意图，不能代替 samples。

每套 samples 以 30 FPS 覆盖完整时长，包含 `blink/sad/annoyed/sleepy/gazeX/gazeY/browLift/mouthWeights`。最新版 Success / HeadClick 还含 `happy`，用于 `Pet_BrowHappy_Review`（在 HeadClick 中为零）。当前 V7 C# 直接插值和写入 blink、sad、annoyed、sleepy、嘴型；EyeWide 固定 0，gazeX / gazeY / browLift 不在该 C# 中直接写入，实际视线与眉骨运动需配套面部骨骼 Clip。同步新笑眉时需扩展 C# Sample / 插值 / 写入 / 中断起始值，并将缺省 `happy` 当作 0；仅替换新版 JSON 会被旧脚本忽略这个字段。

嘴型槽位固定顺序为 `[300, 706, 705, 604, 605, 305, 401, 200]`。第 8 槽 200 为三角张嘴，用于 HeadClick 受惊；前 7 槽兼容早期配置。`mouthWeights` 同顺序、非负、归一化。Shader 使用 `_MouthBlendEnabled`、`_MouthTiles0/1` 和 `_MouthWeights0/1`；不要只改 `_MouthTile` 而绕过权重混合。

## 7. 特殊表情 Squeeze：`><` / `>o<`，冻结 V15

意图是挤眼的小圆口反应，适合作为短暂特殊回应；不自动绑定 Success / HeadClick，也不新增共享情绪枚举。

双眼是左右镜像的 Q 版透明眼线贴图，置于眼眶前的独立平面，绑定 Head，不贴着脸的曲面变形。使用整理过的圆润边缘，V15 线条略加粗后整体缩至上版 94%。当前不是直接裁剪原立绘的细眼线。嘴部使用原图集 605 加 `Pet_TestRoundMouth_Review` 形成小圆口。

完整过程 2.4 秒，30 FPS 第 1–73 帧：Neutral → 真正闭眼遮住眼眶 → 隐去旧眼线，显示 `><` 并切入圆嘴 → 保持 → 撤去新眼线和嘴型 → 睁眼恢复。关键完整表情在第 37 帧附近。曲线有淡入淡出，不能只打开贴图而让原眼睛继续叠在后面。

## 8. 特殊表情 Omega：`-ω-`，冻结 V17

意图是闭眼、满足、略带俏皮的小表情。双眼复制原模型眉毛的一侧几何和 UV，再镜像生成另一侧，压平大弧度、保留柔和端点；原眉毛没有被替换。嘴型为 Head 绑定的独立对称 ω 圆弧网格，不占原图集新单元。

V17 在 V16 的中心线、位置与时序上仅加粗眼线 1.55 倍、嘴线 1.65 倍。完整 2.4 秒，第 1–73 帧：Neutral → 闭眼与 ω 嘴进入 → 原眼线 / 原嘴淡出，新线条完整显示 → 短暂停留 → 撤销遮挡及新几何显示 → Neutral。完整关键帧同样位于第 37 帧附近。

## 9. 两个特殊表情的 Unity 移植与复位

参考工程见 `Material/CHDDD/Integration/UnityExpressionReference/`。`Assets/Review/expression_samples.json` 是已经实际用于 Unity 渲染的采样：每种 58 帧，24 FPS，时长 2.4 秒，`time` 单位秒。最后一张为约 2.375 秒，**不含精确 2.4 秒端点**；Player 驱动完成时必须显式回到 Neutral，不能把最后样本误当成完全复位。

| 采样字段 | Unity 输出 | 说明 |
| --- | --- | --- |
| `shapes[]` | 按 `shapeNames[]` 写 BlendShape ×100 | 包含 5 个原形变、上弧笑眉、禁用的旧实验形变与圆口形变 |
| `mouth[]` | `_MouthWeights0/1` | 按 `mouthTiles[]` 顺序，8 槽 |
| `eyeSkinMask` | Face 材质 `_ReviewEyeMask` | 闭眼区域旧眼线及重复描边处理 |
| `oldEyeMask` | EyeMouth 材质 `_ReviewEyeMask` | 隐藏旧眼部条带，保留非眼区域 |
| `squeeze` | Squeeze 材质 `_Opacity` | `><` 平面显示 |
| `omegaEye` / `omegaMouth` | 对应材质 `_Opacity` | `-ω-` 新线条显示 |
| `hideMouth` | 原嘴 Shader `_ReviewHide` | Omega 时撤去旧嘴 |

Face Shader 还使用 `_ReviewFaceNormal` 稳定闭眼区域着色，参考 Editor 驱动按当前 Head 绑定平面求法线；移植后需在角色运动时更新，不能把它留成另一帧的世界法线。顶点颜色 `UnityReviewMasks` 为线性 RGBA：R=闭眼皮肤区域、G=闭眼接缝清理、B=旧眼部插片、A=1。导出 / 导入不得丢失或另作整体色调乘色。

所需 Shader：`CHDDD/ReviewFace`、`CHDDD/ReviewEyeMouth`、`CHDDD/ReviewOverlay`、`CHDDD/ReviewMouthAtlas`，源码在参考工程 `Assets/Review/Shaders/`；处理基于 Built-in，不能直接声称支持 URP / HDRP。Overlay 使用透明边缘与原 Head 蒙皮，不使用贴脸 Shrinkwrap。材质与 Gamma 色彩空间沿用已经渲染的测试配置，Unity 和 Blender 的灯光 / 颜色仍有差异。

当前 `CHDDDUnityExpressionReview.cs` 位于 Editor，仅用于采样、场景和截图，不是可在 Player 里调用的 `PlaySpecialExpression` API。运行时须实现自己的局部演出控制器，保证表情独占脸部写入，并和既有基础 / 动作面部控制器交接。

复位目标：`squeeze/omegaEye/omegaMouth/eyeSkinMask/oldEyeMask/hideMouth = 0`，旧失败形变恒为 0，撤销圆口 / 新笑眉的临时权重，恢复当前宿主表情或动作面部过程及嘴型归一化。Blender 已验证切换标准动作和表情会复位；该结论不能替代 Unity Player 接入后的中断测试。
