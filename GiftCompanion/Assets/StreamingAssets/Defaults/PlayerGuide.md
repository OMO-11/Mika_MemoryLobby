# 老师的陪伴资料手册

平时不需要 Unity、终端或编辑 JSON。进入陪伴空间，按 Esc，选择「资料与回顾」。

## 音乐

「音乐」里可以选歌、上一首 / 下一首、添加 MP3 / OGG / WAV。当前歌曲一直单曲循环，播放完不会跳到另一首；切换和循环会柔和过渡。

「添加音乐」打开文件选择窗口，选中音乐即可。程序复制一份到资料文件夹，原文件不移动。添加后点击「播放」才切换；「移出歌单」只移除清单记录，音乐文件保留。音量 / 静音在 Esc → 设置中调整。

## 陪伴空间

「陪伴空间」中点击「进入」更换画面，同一人物的历史与记忆继续使用。点击「添加空间资源包」，选择资源提供者整理好的文件夹。当前支持 Spine 4.2，包中包含骨架、atlas、全部 PNG 图集，推荐附带 space.json；无需玩家编写代码。

资源版本不符、文件缺失或不能播放时，原空间会保留。新空间没有专门适配表情 / 互动时，先显示基础待机；不是所有骨架都自动具备摸头和口型。

## 人物卡

「人物卡」可以直接修改名字、性格 / 说话方式、与老师的关系与边界，点击「保存并应用」。修改后共用原历史，不会新建角色或清空记忆。只有老师主动保存才能修改，自动记忆和日记不会改写人物卡。保存前可关闭面板放弃未保存修改。

## 我们的相处日记

在「我们的相处日记」点击「回望从相识到现在」，手动整理首次使用以来的完整聊天。不会每天自动生成，也不会只查看最新几轮；长历史会分批翻阅，可随时停止。

日记以人物第一人称回顾共同话题，以及对话中表达过的感受与关系变化，不是好感度评分或永久人格修改。已遗忘内容不纳入；原始聊天仍可在 MomoTalk 查看。没有新聊天或人物卡变化时会复用相同回顾，不重复请求。

日记同时保存到记忆数据库和 Diary 文件夹中的 Markdown。点击「打开日记文件夹」可复制、阅读这些文件。日记是程序生成的可读副本；手动编辑 Markdown 不会自动改写数据库或记忆，重要批注请另存副本。更正 / 遗忘来源后，旧回顾会收起，导出文件也会更新，可重新生成。导出中断或副本缺失时会在下次打开或启动时补回，已有成功副本在普通查看时不覆盖。文件名使用 UTC 时间与唯一编号，正文仍显示本地日期。

## 文件与维护

「资料文件与维护」可以打开资料文件夹、重新读取外部修改、生成《资料检查.md》、查看本说明。一般只用界面按钮即可；资源提供者或熟悉文件的老师也可编辑独立资料：

- Config/bgm_playlist.json：歌曲标题、相对文件路径、当前曲目、过渡秒数，Repeat 保持 one；默认允许 180 分钟以内的音乐，可由资源提供者调整。导入文件须不超过 200 MB。
- Config/companion_spaces.json：空间标题、资源描述文件路径、当前空间。
- Content/Spaces/.../space.json：Spine 4.2 版本、图集与骨架文件名、待机动画、画面配置。
- Config/character_card.json：人物卡；角色 ID 保持不变。
- Config/diary_policy.json：长历史整理的分批与输出长度设置。
- Config/settings.json：音量、字幕字号等普通设置。
- memory.db：共享角色状态、原始聊天、记忆和日记。不要用文本编辑器修改。
- Diary/：可读日记副本；Logs/：排查日志。

资料默认位于 Windows 本机应用数据文件夹，点击「打开资料文件夹」可直接找到。开发者在 Unity 里运行时使用工程 UserData 文件夹。替换程序时保留资料；如需备份整个资料文件夹，先正常退出程序。秘密 Key 文件单独保存，不要随资料报告发给别人。

保存配置会保留上一版为 .previous.bak，文件损坏时原文件保留并使用可用资料。需要恢复可请资源提供者协助，或把正确备份改回原文件名，再点击「重新读取资料」。日记副本不保留旧的遗忘内容备份。

若保存时程序意外中断，请先重新启动，让程序尝试恢复待提交资料；不要手动删除 .pending 文件。正常保存结束会自动清理这些临时文件。

资料检查核对文件是否齐全，不能代替代码审计。项目源码与接口说明由项目提供者维护，玩家无需改代码即可添加资源。正式语音、复听、自动化工具和跨机一键安装将按后续阶段实现。
