# 声音与复听

进入陪伴空间后，程序会自动准备 Mika 的中文声音。第一次准备和第一次朗读可能较慢；准备期间的回复先用文字显示，就绪后的新回复使用语音，无需打开终端或另外安装 Python。

## 平时怎么用

- 按 Enter 输入，发送后会分句朗读。字幕跟随当前声音；等待下一句时可能短暂停顿。
- 发送新消息会立即停止旧声音，开始处理新消息。Esc → 设置 → 声音与复听，也可点击“停止当前回复 / 复听”。
- 在“声音与复听”中调整角色声音音量，选择开启或关闭，点击“保存声音设置”。背景音乐音量仍在原设置页。
- 角色发声时背景音乐会柔和降低，结束后恢复原音量，不会自动换歌或解除音乐静音。
- 声音暂时不可用时仍可文字聊天。可以稍后点击“重试语音”；程序会重新检查自己的语音资料，不需要手动结束其他程序。

## 复听过去的话

Esc → MomoTalk，在有完整语音缓存的回复下点击“复听”。复听直接读取以前保存的声音，不需要 DeepSeek Key，也不需要启动语音模型。

旧版文字记录、未完成回复或已丢失音频的记录会显示“无缓存”。程序不会为了复听自动重新生成声音。实时对话优先，发送新消息会停止复听。

“声音与复听”显示缓存占用，点击“清理已缓存的语音”只清理声音；原始聊天、共同记忆、日记和人物卡仍保留。清理后，过去的记录不能再复听；未来新回复仍可生成新的缓存。

## 文件在哪里

Esc → 资料与回顾 → 资料文件与维护 → 打开资料文件夹。

- Config/voice_runtime.json：语音运行时与队列、音乐压低参数。正常使用不必手改；资源提供者维护时可以读取。
- Config/settings.json：语音开关与声音音量，和其他普通设置一起保存。
- AudioCache/：逐段 WAV 声音文件；数据库保存它们与聊天消息的对应关系。不要随意改名或移动其中的片段。
- Logs/：程序诊断与语音服务状态，不需要把 Key 发给维护者。

语音模型保存在程序使用的 Runtime/GPT-SoVITS 中，与人物卡、记忆分开。当前开发版请使用 Start-Phase4.cmd 启动，让程序自动找到已准备的运行时。换机器使用的安装和体积优化将在后续分发阶段完成。

切换陪伴空间仍使用同一个人物和记忆。已适配的大厅支持声音口型；其他空间若没有对应嘴部映射，可以正常播放声音并显示字幕。
