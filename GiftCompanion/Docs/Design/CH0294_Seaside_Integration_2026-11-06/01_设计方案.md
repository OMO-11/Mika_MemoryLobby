# 海边记忆大厅资源补充：设计方案

日期：2026-11-06。状态：**用户于同日批准接入，并要求菜单仅作过渡占位、复用既有空间接口；以下为初始设计记录，最终实现以《03_接入与验证报告》为准。**

本轮作为 V2 收尾后的一个资源补充批次，建议一次交付，不再拆成需要逐阶段批准的大版本任务。批准范围为本方案中的资源接入、菜单、功能适配和验证。

[打开交互示意](02_菜单交互示意.html)。示意使用交付包中的待机截图与浏览器毛玻璃，供审核位置、层次和交互；不是 Unity 已实现画面，也不代表动画或运行性能已经验收。

## 1. 审查结论与接入依据

**可以并入，须进行局部渲染和业务桥接适配。**这次变更是同一角色的另一处陪伴空间，不创建另一份人格、历史或记忆。

| 核对项 | 当前发现 | 设计处理 |
| --- | --- | --- |
| Unity | 两边均为 6000.3.7f1 | 沿用当前固定版本 |
| Spine | 两边均为 spine-unity 4.2-2026-05-29；688 个文件逐文件 SHA-256 一致 | 复用主项目已有 runtime，不导入第二套 |
| UI / 输入 | 两边均包含 uGUI，Input System 1.18.0 | 复用现有 uGUI/TMP、输入与焦点规则 |
| 渲染 | 海边为 URP / Linear；主项目为 Built-in / Gamma | 保持主项目管线与全局色彩设置，对海边材质做局部适配并与 PNG 对照 |
| 角色载体 | 海边使用 SkeletonGraphic，当前大厅使用 SkeletonAnimation 与世界相机分层 | 通过陪伴表现适配层接入，不把原世界相机加载器直接套到海边 |
| 现有空间目录 | 已有选择/保存，但默认清单只在首次创建时播种 | 更新时合并缺失的内置海边条目，保留既有选择、导入空间与玩家改名 |
| 背景与动作 | 已有动态海面/星空、修复取景、入场白光、抚摸、轻微待机表情 | 保留已修复效果，不再套用窗边运镜 |
| 音频与特效 | 交付说明明确未补齐原游戏语音与独立漂浮光点 | 沿用本项目真实对话/TTS/BGM，不增加不存在的原游戏配音或粒子 |
| 交付验证 | 附有历史播放报告；本次整理仅做静态核对，未重跑 Unity | 接入后重新做主项目和独立程序验收，历史报告不视为本次通过 |

主宪法对应约束：§1 沉浸优先与单活动角色、§4 Bootstrap 单一服务根、§6 CharacterCore 与渲染解耦、§12 Spine Adapter、§13 Esc 菜单、§18 打断、§19 BGM，以及现有 V2 的未保存确认、维护入口与资料保护规则。

海边自身使用的三个控制脚本、修复材质与依赖需要选择性迁移；交付工程的 Packages、ProjectSettings、教程、URP Volume 和灯光不整体复制。交付说明中的迁移建议作为参考资料，不替代主项目架构约束。

## 2. 玩家看到的变化

### 2.1 选择另一处空间

入口沿用 **Esc → 陪伴空间**，清单保留原“记忆大厅”，新增“海边记忆大厅”。每个条目标明“当前空间”或“进入”，保留原有添加空间能力。

- 老玩家更新后继续留在原来的空间，新玩家默认也保持原大厅；主动选择海边后记住该选择，下次启动恢复。
- 进入不同空间前停止并等待当前对话/复听收尾，关闭临时输入但保留未发送草稿，不自动提交。
- 候选资源和第一帧准备好、选择保存成功后才完成切换；失败保留原空间与当前页面，给出简短提示。
- 切换成功后收起选择页，进入目标大厅的人物画面；海边播放已有入场，原大厅进入人物起点。
- 重复选择当前空间不重建画面，不重播入场。
- 仅有一个空间在推进角色动画和接受输入；不启动第二套 CharacterCore、数据库、LLM 或语音进程。

继续使用原 BGM 曲目、暂停位置、静音和音量偏好；换大厅不强制换歌。人物名称、人物设定、历史、长期记忆、日记、Key、语音模型及语言偏好保持连续。

### 2.2 海边主画面

保留交付包的角色比例与纵向视野：横屏扩展两侧背景，窄窗口向角色焦点裁切，沿用已修复海面垫底和背景顶点延展。不得横向拉伸角色，也不重新引入放大黑边。

已有入场约 14 秒，使用交付包的 1.25 倍速与白光衔接。它属于资源本身的入场表演；本轮不新增人物到菜单的摄像机移动。

左上音乐中枢、临时输入、左下字幕和时间显示沿用当前视觉体系。初次进入海边时短暂提示“Enter 说话 · Esc 菜单”，随后淡出，不新增常驻功能侧栏。原生动画事件不播放缺失的游戏配音。

入场时按 Esc 可立即打开菜单，入场在菜单后继续；关闭菜单不重播。入场时按 Enter 则平滑结束入场并打开输入，保留草稿，不自动发消息。开启“减少动态效果”时跳过入场特写与白光，使用简短淡入；保留必要的基础待机。

### 2.3 Esc 毛玻璃菜单

海边大厅使用固定屏幕菜单，按 Esc 即开，不寻找时钟锚点，也不等待运镜。原大厅继续使用已完成的窗边菜单与连续帘幕/流星效果。

毛玻璃分为三层，所有数值均为待 Unity 视觉核对的初始设计值：

1. **现场背景**：人物、海面、星空继续实时播放。
2. **毛玻璃背景**：现场画面轻度模糊，1280×720 参考下视觉半径约 8–12 px；叠一层约 18–24% 的冷色暗罩，仍看得见人物和海面。
3. **清晰 UI**：左侧半透明蓝紫玻璃面板，约 36–44% 着色、1 px 淡白边、约 18 px 圆角；暖白字与淡粉焦点沿用 V2，文字本身不参与模糊。

菜单面板在 1280×720 下建议位于 x=56、y=64，宽约 360、高约 590，避开中右侧人物面部。标题“海边记忆大厅”，下面依次为：

| 菜单项 | 作用 |
| --- | --- |
| 聊天记录 | 现有历史、分页与缓存复听 |
| 日记 | 现有浮字阅读、批注与回望 |
| 陪伴空间 | 切回原大厅或进入其他空间 |
| 人物设定 | 编辑同一份人物卡 |
| 设置 | 声音、画面、资料与现有维护/退出入口 |
| 回到未花 | 关闭菜单，回到海边人物画面 |

每行至少 44 个逻辑像素的点击高度，支持鼠标、Tab、Enter，焦点有淡粉提示。点击菜单外也可返回人物；已打开确认弹层时先处理弹层，不穿透。

海边进入聊天记录、日记或设置后，继续使用同一个毛玻璃背景，沿用已验证的内页内容与排版。小窗口下菜单缩进安全区，必要时菜单内部滚动，不挤压主场景、也不让退出入口落出屏幕。

### 2.4 返回与输入优先级

| 当前状态 | 按 Esc |
| --- | --- |
| 海边人物画面 | 打开毛玻璃菜单 |
| 临时输入 | 收起输入，保留草稿；再次 Esc 才打开菜单 |
| 一级菜单 | 收起菜单，回到人物 |
| 聊天记录 / 日记 / 人物设定 / 设置 / 空间选择 | 回到一级菜单 |
| 音乐管理 / 记忆管理 / 资料检查 | 沿用现有二级返回路径 |
| 有未保存修改 | 先出现现有“继续编辑 / 放弃修改并返回”确认 |
| 保存或切换已进入提交 | 防重复输入，完成提交或回滚后才离开 |

打开菜单本身不取消当前对话。后台语音照现有规则继续，菜单期间不把字幕盖到菜单正文上；回到人物时按当前有效轮次恢复表现。切换空间才主动收尾当前轮次。

菜单/内页/确认框出现时屏蔽场景抚摸，松开正在进行的抚摸，不允许点穿；背景动画不因 UI 捕获输入而暂停。关闭后恢复可交互状态，不清空或重建待机轨道。

## 3. 工程实施方式

### 3.1 选择性导入与版本兼容

- 原交付目录保持只读；将需要的 CH0294 骨架、四张贴图、图集、资产、材质与三个控制脚本复制到正式资源目录。
- 保留 `.meta` 前先核对 GUID 冲突；相同 runtime 直接复用，不能靠覆盖已有目录解决冲突。
- 海边资源主体目前约 6.73 MiB（24 个文件，含 meta）；最终安装增量还需构建后测量，不按完整独立工程大小估算。
- 建立带版本的内置空间注册，明确区分默认大厅、海边和普通导入空间的表现类型；不继续把所有 `Builtin=true` 条目都当成原大厅的 defaultProfile。
- 老配置加载时仅补缺失的海边内置条目，采用现有原子保存/回退方式；不覆盖整个 `companion_spaces.json`。数据库版本和备份协议不变。

### 3.2 最小表现桥接

在 `CompanionPresentation` 周围建立最小的空间表现适配，原大厅仍走现有加载器，海边保留 `SkeletonGraphic` 控制器。

统一提供：就绪/错误、当前空间、状态与情绪、UI 输入捕获、抚摸取消、实际语音驱动、取景缩略图、卸载与菜单方式。同步处理现有 `Loader` 直接依赖，覆盖导航、语音、截图和窗口缩放，不能只新增一张可看的画面。

海边 Thinking / Speaking / Touched 与自动表情按优先级互斥，避免多个组件同时写同一轨道。口型跟随项目真实语音播放进度/能量，不能拿固定的 Talk_01 剧情动画冒充任意合成语音；缺失的表情按既有协议回退。交付包里未绑定的游戏语音事件保持静默。

暂不为海边填写窗边参数，不让 `CompanionWindowView` 的 CH0069 分层、裁切、前景遮挡及运镜逻辑接管它。原大厅连续细纱、星空与流星的行为保持有效。

### 3.3 实时模糊

海边 Canvas 使用可被场景相机采集的渲染方式。只采集场景，排除菜单、输入、字幕和确认框，避免递归模糊或 UI 拖影。

初始方案为半分辨率 RenderTexture + 两次可分离模糊，再将结果作为屏幕背景显示，叠加半透明着色。菜单关闭时释放或停用额外模糊渲染，不做逐帧 CPU ReadPixels。窗口尺寸变化时重建匹配比例的纹理，不拉伸、不露黑边。

保持 Built-in / Gamma，不增加 URP 依赖，不更换全局 Graphics/Quality 设置。对海边材质的色彩/混合做局部适配，特别检查透明发丝、海浪边缘、加色星光与白光，确保没有重复 Gamma 转换或黑色边缘。

“减少动态效果”关闭面板位移与缩放，保留短淡入淡出。模糊不可用时提供半透明深色底的可读回退，并记录真实降级；不能以深色底截图冒充毛玻璃已实现。

## 4. 批准后的工作顺序

本批次内连续完成三步，不再按步骤反复请求批准：

1. **资源与表现适配**：导入、局部材质、构图、入场/抚摸/状态、旧配置补齐与切换事务。
2. **菜单与功能接通**：Esc 毛玻璃、输入优先级、所有业务页、语音/缩略图与减少动态效果。
3. **验收与交付**：独立程序、双大厅往返、截图/录屏、实际性能记录、文档和独立补充候选目录。

已有 `Releases/Gift-V1-Closeout` 与 `Releases/Gift-V2-Candidate` 保留，新的候选另建目录。原素材、冻结视觉档案和真实用户资料不用于测试、不被覆盖。

## 5. 验收标准

- 现有配置更新后能看见两个内置空间，原选择、自定义空间和人物卡不丢；海边选择保存后重开可恢复。
- 隔离资料中双向切换至少 10 次，始终同一 Core/DB；旧空间、渲染纹理与输入监听及时释放，没有双人物/双语音进程。
- 候选加载、选择保存失败及快速重复点击均可安全留在原空间；Esc 不绕过未保存确认。
- 海边原入场、白光、长按/松开/移出/失焦抚摸与待机表情有效；菜单开启后无误触，海面/星空/人物继续推进。
- 实际聊天输入、中文 IME、打断、文字降级、字幕和已有 TTS 播放链路可用；不新增原游戏语音承诺。
- 菜单和所有既有内页均能到达，切回原大厅后窗边运镜、细纱/星空/流星继续有效。
- 960×540、1280×720、1920×1080、当前显示器最大化和宽高比变化下无明显黑边、角色不拉伸、毛玻璃文字清晰。
- 比较海边菜单关闭/打开的帧耗时，记录实测开销；验证背景是真实动态采集。历史报告帧数与预览 GIF 不作为新程序性能证据。
- 运行相关逻辑、场景与独立程序回归；交付实际截图/往返录屏、资源指纹、构建入口与未覆盖范围。
