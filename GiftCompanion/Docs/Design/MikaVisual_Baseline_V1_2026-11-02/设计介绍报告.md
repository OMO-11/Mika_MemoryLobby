## 1. 这轮视觉工作最终解决了什么

这轮工作将原先分散的字标、时钟、背景音乐入口、菜单按钮和对话框，逐步整理成“人物陪伴区”和“窗边功能区”两个相连的空间。人物画面承担陪伴、表情与对白；窗边承担时间、日期与功能入口。通过一次连续运镜连接二者，减少跳页和大面积面板对记忆大厅的打断。

最终保留原场景的蓝紫夜色、星空、窗框、花瓶与人物构图。玩家点击人物后方的时间区域后，视角靠近并经过人物，来到较正面的窗边。菜单位于左下区域，右上为24小时数字时钟及日期；夜空留出较大的空白，让流星、月光和轻纱成为环境的一部分。

本轮主要完成了三类工作：明确主场景视觉规则；建立真实资源测量与分层依据；制作并反复调整可点击原型和运镜 GIF。没有将视觉修改混入聊天、语音、记忆数据库或已交付候选包。

## 2. 项目准则与设计目标

依据《项目总宪法》，场景首先应让玩家感觉人物存在于其中。功能不能把陪伴空间变成普通聊天客户端。时间、菜单和音乐控制应尽量附着于场景，技术进度、接口信息与诊断内容继续留在维护区域。

“一切皆文件”落实到本档的方式是：实际素材、字体、独立参数、矢量图标、来源清单、设计说明、代码参考和验证记录均可直接打开查看。当前摄像机路径和界面尺寸不只存在于聊天描述里，也保存在可读取的 JSON 中。

本次定稿的目标如下：

- 让人物仍是陪伴画面的视觉中心，避免大型对话框和菜单挡住面部。
- 让前往窗边和回到人物的过程连续、缓和，保留空间关系。
- 让时间和菜单从开始就属于窗边，运镜途中只改变投影大小与遮挡，不突然消失或换成另一套屏幕界面。
- 让终点接近正面，整体略退并上抬，露出上方星空、窗框和窗台下沿。
- 让玩家不需要理解程序目录，也能从本文件夹的阅读入口看到效果和设计说明。

## 3. 我们已经确定的整体风格

整体主题延续“星夜茶会”的方向：蓝紫色夜空作为主体，柔和暖白文字作为信息层，粉色细线用于少量图标。人物、星月、羽翼、花饰和夜间光线来自现有素材，不另造一套与人物割裂的装饰系统。

主场景没有额外的卡片底板，尤其不使用椭圆毛玻璃包住音乐按钮或场景菜单。文字和图形保持克制，背景真实结构负责划分空间。月光和纱帘只补充轻微层次，不制造闪屏或强烈光效。

| 元素 | 确定方向 | 当前覆盖情况 |
|---|---|---|
| 人物与夜景 | 使用现有 CH0069 记忆大厅，保留原人物造型与构图 | 已导出真实分层，并用于当前 GIF |
| 窗边终点 | 正面、整体略退、稍向上，天空留白更多 | 第七版已确认 |
| 菜单 | 左下区域，萝莉体，紧凑单列，透明背景 | 当前运镜原型已体现 |
| 时间日期 | 右上，HH : mm；日期另起一行 | 当前原型已体现；交互预览按上海时区实时显示 |
| 音乐中枢 | 左上当前曲名，透明按钮靠近显现 | 规则和图标已明确，完整控件尚未合并进运镜原型 |
| 对白字幕 | 左下白色细描边，无框、无姓名条 | 静态原型验证过；当前运镜 GIF 无对话演示 |
| 日记、设置等展开页 | 延续窗边浮字体系，日记采用透明正文 | 本轮内页初稿已确认；功能接入仍待完成 |

## 4. 人物画面与窗边空间的关系

人物画面保留原记忆大厅的倾斜构图。时间与菜单实际放在窗边位置，允许被头部、发饰、帘子和花瓶等前景挡住。被遮挡不是淡出：当镜头经过人物，遮挡解除，同一组文字自然显露。

窗边终点则通过镜头旋转抵消窗面的倾角。界面在终点呈正向，避免之前版本把菜单和时钟继续斜排，造成画面越来越歪的问题。这个正面效果是最终方向，不能因为追求所谓立体感再次改回斜向终点。

## 5. 运镜流程与节奏

| 时间区间 | 画面行为 | 设计作用 |
|---|---|---|
| 0—1.0秒 | 停留人物画面，模拟点击后方时间 | 交代交互入口和空间起点 |
| 1.0—4.2秒 | 向窗边推进，经过人物，逐渐转正 | 用近景遮挡与分层速度建立纵深 |
| 4.2—8.4秒 | 窗边停留，展示菜单、时间日期和流星 | 让玩家有时间观察终点构图 |
| 8.4—10.8秒 | 演示点击“回到未花”，反向返回 | 检查往返时同一界面的空间一致性 |
| 10.8—11.6秒 | 人物画面短暂停留，随后循环 | 便于反复比较整条路线 |

以上是 GIF 演示时间，不代表产品会自动把玩家送回人物画面。交互预览到达窗边后可以一直停留，只有点击返回入口才回去。两个阶段使用缓入缓出的运动，人物近景掠过时加少量模糊，避免直接把人物淡掉。

## 6. 最终摄像机与坐标参数

坐标基于原始1280×720逻辑画布，向右为 x 增大，向下为 y 增大。它们是当前原型的标定坐标，不可直接当成 Unity 的世界单位或摄像机角度照搬。

| 参数 | 第一版确定值 | 说明 |
|---|---|---|
| 终点中心 | (955, 268) | 相比上一版向左、向上调整 |
| 终点缩放 | 2.3 | 从2.5整体退镜，场景中物体线性缩小约8% |
| 镜头旋转 | -26.8165748° | 与窗面正26.8165748°相抵，终点正向 |
| 界面独立缩放 | 1 | 撤回只缩小文字的0.85方案 |
| 菜单世界锚点 | (845, 195) | 结合新镜头后呈左下布局 |
| 时间世界锚点 | (1060, 190) | 呈窗边右上布局 |
| 原帘层深度系数 | 1.05 | 保留一些帘子，不让其完全掠出画面 |
| 近景人物深度系数 | 2.5 | 人物比背景更快通过镜头 |
| 人物附加位移 | (-700, 300)×进度平方 | 让人物真实移出取景，而非透明消失 |

“整体缩小”必须调整摄像机取景，不能再次理解成只调小菜单或字号。第六版曾误解这一点，第七版已纠正。界面独立缩放在当前基准中恢复为1。

当前视口逆投影四角全部落在原始渲染图范围内，更多上方星空来自原素材的有效取景，不是用空白画布冒充。对应记录位于06_验证记录。

## 7. 菜单、时钟、日期和文字细节

菜单为六项紧凑单列：聊天记录、日记、陪伴空间、人物设定、设置、回到未花。基础字号16逻辑像素，行距18.5，没有额外拉大字距；左下位置保留夜空中心和右上时间的留白。

时钟使用24小时“HH : mm”，小时与分钟均补齐两位。日期下方排列为“yyyy.MM.dd”。时间基础字号32，日期12；GIF固定示例为21 : 06和2026.11.02，便于每次比较布局。交互预览使用 Asia/Shanghai 与 h23 格式，不出现 AM/PM 或24:00。

时间、日期和菜单均使用玩家提供的萝莉体。菜单透明度固定0.78，时间日期固定0.76；这里的固定指不随运镜进度改变，不是强制要求将来所有背景都套同一对比度。正式程序还需在实际画面、DPI及用户设置下核对可读性。

本次没有保留大型块状加宽数字、梯形透视、21 06旧分组样式或指针钟。最新明确的“HH : mm＋日期”优先于早期不带冒号的探索要求。

## 8. 字体、色彩与图标

字体由用户给出的系统名 Lolita Regular 定位到实际文件。文件已归档在03_字体，页面通过明确的字体加载等待流程使用它，验证记录确认 loaded，不使用楷体或幼圆冒充。

| 项目 | 当前值或来源 | 用途 |
|---|---|---|
| 萝莉体 | Lolita.ttf，11,949,844字节 | 窗边菜单、时钟和日期 |
| 默认中文正文 | 源项目 Noto Sans CJK SC | 原有阅读页面；本档不额外复制整套正文资源 |
| BGM曲名字体 | Georgia斜体，26逻辑字号 | 保留原字标的观感 |
| 夜景底色参考 | #232943 | 场景空底，与原素材夜色一致 |
| 时钟文字 | #F5E8E8，alpha 0.76 | 暖白，避免过硬纯白 |
| 菜单文字 | #F5EADF，alpha 0.78 | 微暖的功能文字 |
| 月光补充 | #DBE9FF18等透明渐变 | 轻量光带，不替代原场景光照 |
| 图标细线参考 | #EAC3D3 | 双星、瑞士卷和音乐按钮 |

重叠星星使用标准五角星几何，避免早期手绘草图误导成不规则形状。瑞士卷保留简单线稿。两者点击切换的是装饰图标，不是换歌曲或换场景。

独立SVG已按功能拆分到04_图标与视觉规则，包括双星、瑞士卷、上一首、下一首、暂停、播放、音量。图标可以直接在浏览器打开检查，不需要先启动 Unity。

## 9. 音乐中枢与字幕的已确认规则

左上角显示当前BGM曲名，替换最初的“Mika”字样；下方“与你一起的片刻”删除。只保留上一首、下一首、暂停或继续、音量四类控制。按钮透明平铺，鼠标靠近或键盘聚焦时显示，离开后收起。

主场景不展示歌曲封面、歌单或独立背景音乐页面，菜单也不再列“背景音乐”。后台独立清单、玩家添加歌曲的能力、单曲循环、手动切歌与淡入淡出继续属于已有音频能力，不能因页面精简而删除。

当前运镜原型左上角只画了简化星标和曲名，没有合并完整音乐按钮逻辑。归档将该规则、矢量图标和组件CSS作为确定的实现依据保存，没有把这个简化示意宣称成已完成的音乐中枢。

对白采用左下方白色字幕与细描边，不要恢复厚底板、姓名条或大对话框。输入框的视觉已删除，但实际聊天输入方式仍需后续单独确认；这不等于删除后端聊天能力。字幕继续服从既有语音分段时序，不能全文先出现、语音开始后再从头逐句重放。

## 10. 夜空、月光、纱帘与流星

星空以原场景纹理为主，加入少量低幅度星点变化。两道流星从演示4.9秒、6.75秒开始，每道约1.1秒，仅在窗面内绘制，亮度平缓，不伴随闪屏。它们只补充夜间气氛，不作为需要频繁操作的提示。

月光用场景内的柔和渐变带补充窗边与窗台的明暗层次。轻纱是程序绘制的半透明曲面与细褶线，并有小幅慢摆；原有帘子仍来自真实导出的资源层。这些补充不是新增绘画素材或对原纹理的不可逆修改。

原素材、取景分层和程序效果在归档中分开保存。实现人员可以独立调整纱帘强度或流星间隔，不需要修改人物贴图。

## 13. 当前实现方式及其边界

这是Canvas的2.5D分层参考。背景、帘子、人物以不同速度和深度系数运动，叠加场景固定文字及程序效果，建立接近和经过人物的感觉。它不是把原本平面的Spine场景自动变成完整三维房间，也没有制作新的人物背面。

时间/菜单先随背景绘制，随后由帘子和人物覆盖。点击位置通过相同的镜头矩阵逆变换回场景坐标，这使点击区域与显示位置一致。交互预览中的时钟前进、返回按钮和完整演示可用，其余业务菜单目前为布局占位。

参数为便于file本地双击打开，既保存成独立motion.json，也嵌入HTML。当前原型修改参数时必须同步两处。正式实现应改为统一读取独立文件，避免维护两份数据；不能把这个离线预览技巧照搬成两个生产配置来源。

素材复制不等于完成Unity集成。原工程的聊天、记忆、TTS、BGM服务和已封存候选包都没有在本轮被视觉原型替换。

## 14. 后续 Unity 实现建议与顺序

先将当前参考作为视觉目标保存，再在独立实现分支或工作副本中接入。顺序建议是：读取主题和空间参数；搭建人物/窗边两个相机状态；加入时间菜单的场景固定变换与点击；验证动态人物遮挡；接回功能入口和音乐字幕；最后逐项精修光感、字体尺寸和不同分辨率。

需要将逻辑1280×720坐标转换为当前Unity相机、Canvas或场景层坐标，不能把本报告中的2.3缩放或-26.8166°直接设成生产相机数值。应根据实际渲染结构选择World Space Canvas、相机场景平面或等价的空间映射方式，保持效果一致。

切换时要处理连续点击、返回中再次前进、窗口缩放、失焦、动画中途退出、字体缺字与极端字号。触摸人物与点击后方时钟需明确命中优先级，避免点击头部却跳到窗边。可为需要的玩家提供减少动态效果或直接到达窗边的选择，但此功能尚未实现。
