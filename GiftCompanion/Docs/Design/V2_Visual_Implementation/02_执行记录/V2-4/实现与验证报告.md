# V2-4 聊天记录与浮字日记

2026-11-03，Asia/Shanghai。与 V2-3 联合接入。已选透明浮字方案使用真实服务与保存资料，不把设计稿正文或验证文字写入正式玩家数据库。

## 1. 聊天记录

聊天记录为纵向布局，称呼/时间与消息正文分层。老师消息缩进，复听和本轮不参与回忆操作紧邻对应角色消息；原分页、未完成标识、空历史状态继续使用 History 服务。无完整缓存禁用复听，不重新合成；实时对话优先。离开历史页立即停止该页复听，关闭历史查询的令牌不取消无关实时轮次。

[聊天记录截图](Native/聊天记录.png) 中内容来自隔离验证库，包含完整缓存和缺失缓存两种情况。长消息按实际内容宽度换行并参与布局高度计算，保留滚动与更早/较新记录操作。

## 2. 浮字日记

采用已确认的透明正文、暖白文字、萝莉体、自然段与可调字号/行距，没有薄信笺或正文底板。导航高亮当前页，元数据独立显示范围，正文区滚动且柔和裁边。保留上一篇/下一篇、继续阅读、打开当前 MD、手动“回望至今”和生成时停止整理。

“继续阅读”按当前可见高度向下移动约八成页面；阅读位置按篇目 ID 与状态区分，同篇返回恢复，新篇和失效篇不沿用旧位置。生成操作由玩家主动触发，沿用从相识至现在的保留对话范围、来源限制与数据库/MD 双份保存。普通重开不覆盖玩家批注；更正或遗忘使来源失效时，旧派生正文收起，不能从日记绕回已排除的记忆。

RelationshipDiary 公开统一的 ExportPath 供导出和打开文件共同使用，避免 UI 另猜文件命名。取消与连接失败有自然反馈；生成按钮在整理中防重复，停止整理只在生成期间出现，未完成的生成不能发布成一篇有效日记。

## 3. 验证与范围

联合 EditMode 165/165、PlayMode 41/41 通过。独立 Windows 验证使用模拟 LLM、生成的本地音频和隔离 SQLite，经真实界面完成草稿、播放、暂停、缓存复听、手动日记生成/取消、保存、批注保留、继续阅读、位置恢复和遗忘失效等流程；细目见 Native/native.json、联合 acceptance.json。

独立界面确实查询/保存数据和播放缓存；模拟文本明确标为“隔离验证”，不用于真实角色人格或共同记忆。未调用真实外部接口，不宣称音色、长期稳定性或所有 DPI/设备已重新验收。图片已人工复核，修正了底部操作重叠和历史截图停在长消息尾部的问题。

冻结设计素材 96 项与 V1 收尾关键文件指纹按 protection.json 记录。Builds/V2Reading 为当前图形/交互验证切片，未附独立语音 Runtime。后续 V2-5 继续整理设置、人物和空间维护内页，V2-6 承担完整兼容与交付装配。

## 4. 用户安排的休眠

本机 powercfg /a 已确认支持“休眠”。在程序退出、验证通过、报告与状态落盘后执行 shutdown.exe /h，不使用强制关闭或关机参数。执行前的安排与系统命令返回状态记录到 hibernate.json；系统真正进入休眠后无法在同一活跃会话中继续观测，因此不把请求记录当作已确认休眠的证据。
