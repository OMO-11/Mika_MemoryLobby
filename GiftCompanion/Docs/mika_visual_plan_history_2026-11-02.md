## 1. 设计方向

主题定为“星夜茶会”：保留当前蓝紫色记忆大厅，加入暖白信笺、淡粉细节、少量柔金与星翼线条。希望整体既有未花明快、亲近的一面，又能容纳安静相处和认真回顾的时刻。

视觉线索来自本地完整CH0069场景中可见的星月、羽翼、花饰与浅色衣裙。正版[未花“星之呼唤”造型说明](https://www.goodsmile.com/ja/product/55281/%E3%83%9F%E3%82%AB%2B%EF%BD%9E%E6%98%9F%E3%81%AE%E5%91%BC%E3%81%B3%E5%A3%B0%EF%BD%9E)也明确采用展开的羽翼、明快神态和裙内夜空的对照。这些作为设计参考，界面主题、文案和布局是本项目提案，不当作新的原作设定。

角色优先：正常陪伴只保留少量边缘控件，字幕与菜单按需出现。淡粉承担亲近感，深蓝保持场景深度，暖白承担阅读，金色用于细线与装饰。不给角色增加默认恋爱身份、专属承诺或好感度数字。

## 2. 视觉系统

| 用途 | 建议颜色 | 使用方式 |
|---|---|---|
| 夜蓝 | #242640 | 场景边缘、暗底、小型悬浮控件 |
| 暖白 | #FBF7F2 | 字幕、日记、菜单正文底色 |
| 淡粉 | #EAC3D3 | 小面积底色、选中底、装饰 |
| 深玫瑰 | #9E4F72 | 主要按钮、选中状态、姓名 |
| 柔金 | #B49A6A | 分隔线、书签、星月图形，不承担小字正文 |
| 正文深色 | #35344B | 所有浅底正文 |
| 次级文字 | #6B6474 | 日期、说明与辅助信息 |

界面常驻控件用深底浅字，展开面板用暖白底深字。正常字号正文按至少4.5:1对比度设计；透明背景按合成后最差情况复核，不能只看色号。错误和危险操作继续用明确文字与独立语义色，不混进可爱装饰。

不透明基础色对比计算：正文深色/暖白11.29:1，次级文字/暖白5.32:1，白字/深玫瑰5.50:1，暖白/夜蓝13.80:1。此计算不替代Unity实际背景合成、字号和不同DPI的复核。

继续使用已有Noto Sans CJK SC，避免为了外观再附带一整套中文字体。标题通过字号和留白区分；英文字“Mika”可少量作为字标。中文正文不使用难读的手写体。1280×720参考：字幕24—28，面板标题26—30，正文20—24，辅助说明16—18；日记继续允许玩家调字号与行距。

图标统一细线风格：星、羽翼、书页、音符、画框和调节线。自制少量线图形，不下载新的整套资源库；不用emoji代替功能图标。纸页以细边、轻阴影和小面积书签表达质感，避免厚重金边、反光玻璃或大面积装饰遮挡。

## 3. 各界面布局

### 陪伴主场景

- 保持完整大厅构图，面部、头部触摸、光环及主要表情区域作为安全区。
- 左上角小型Mika字标，右上角简洁时钟；日期和时钟采用真实本机值，原型时间仅为占位。
- 左下角紧凑音乐入口，右下角菜单按钮。键盘提示初次短暂出现，熟悉后收起；纯欣赏时可隐藏普通UI。
- 主要交互继续是角色、Enter输入、Esc返回；时钟和装饰不拦截角色命中。

### 对话和输入

- 底部一张横向暖白信笺，控制在参考高度约140—165以内，优先避开脸部；长回复按既有分页/语音分段展示。
- 姓名、正文、次要操作分层。等待时保留角色思考动作，“先看文字”作为明确但低干扰的次要按钮。
- 不把全文抢先展示再重新逐句播放；视觉改版沿用已验证的字幕时序。
- 输入时在底部展开同位置输入纸页，保留草稿、中文输入法候选、Shift+Enter与Esc操作。发送和停止要可见、可点，不能只靠装饰图标猜测。

### 临时菜单

- 优先使用左侧约420宽、距边30左右的临时纸页面板；当前场景人物脸部主要位于右侧，避免原先居中大面板直接遮住表情。
- 核心功能以中文纵向排列：MomoTalk、相处日记、背景音乐、陪伴空间、人物设定、设置。每行配一个图标和一句短说明。
- 底部单列返回入口和退出应用，退出不与日常选项紧贴；离开仍沿用原有保存流程。
- 菜单只在需要时展开。未来其他Spine空间可以通过布局配置改为相反方向或安全的居中布局，不把“永远放左侧”写成所有空间共用的固定规则。

### 日记与历史

- 日记采用较宽的左侧纸页，保留右侧角色；长文阅读时可提供更宽阅读模式，字号较大或窗口较窄时优先可读性。
- 日期范围、生成时间、篇目、正文、手动回望按钮各有固定位置。自然段与留白是主体，颜文字只在内容中适量出现。
- MomoTalk使用同套暖白/淡粉消息样式，区分老师和未花，复听按钮紧邻对应消息；保留原分页、来源和遗忘约束。
- 本轮视觉改版不新增时间线、主题检索、来源跳转、自动日记或新关系计算。

### 背景音乐、空间和人物设定

- 音乐页用清楚的当前曲名、单曲循环说明、上下首、静音与添加歌曲；装饰封面是通用线图形，不要求玩家提供封面，不新增音频可视化分析。
- 空间页使用小场景缩略图和明确名称，选中态可见；名称与缩略图读取清单，仍是同一角色与记忆。
- 人物设定页保留“名字、性格与说话方式、与老师的关系与边界”的清楚标签；装饰让位于编辑空间，保存、取消和取回上一版的反馈一致。

### 设置与维护

- 视觉上分为声音、画面与阅读、资料与连接，正文、说明、当前值、保存按钮位置固定。
- 联网、备份、恢复、目录和诊断沿用明确中文名称与真实提示；技术字段可以在这里展开，不在主场景显示。
- 高风险确认保持朴素、清楚：说明实际对象、影响和取消方式，不将删除/重置包装成角色撒娇或剧情选择。
- 分组只整理现有功能，不增加新的设置平台或后台服务。原版画面对照和显示恢复继续保留。

### Home与桌宠

- Home用简短欢迎纸页，主入口为“回到陪伴空间”，次入口为“来到桌面”；体现同一角色，取消无关状态看板。
- 桌宠保留现有3D模型，只统一气泡、输入、临时菜单与确认样式；浅色气泡使用深色正文和细粉边，在明暗桌面上都能看清。
- 桌宠操作授权、敏感确认、点击穿透、拖动和窗口位置行为保持现有规则；气泡自动让开角色，不增加第二个常驻聊天窗。本轮原型没有重绘桌宠模型。

## 4. 动效、适配与占用

展开建议150—220ms淡入并小幅位移，收起100—150ms；按压反馈80—120ms。角色已有Spine动效负责场景生命力，普通UI只补必要反馈；减少动效时直接显示，不阻塞输入。

使用现有Unity uGUI/TMP、Image和简单线图形实现。纸感主要依靠色块与线条，不使用每帧全屏模糊、常驻粒子或新渲染管线。若纹理确有必要，单独评估小尺寸图集；不承诺未经实测的内存或性能数字。

布局以1280×720为基准，检查900×700、1024×768与高DPI、大字号；宽度不足时面板优先占用可读空间、将次要说明折叠，不让原尺寸强行溢出。面部安全区按每个空间的定义调整，不把当前截图坐标当作所有资源的通用坐标。

主题颜色、字号层级、面板边距、圆角、按钮状态与动效参数进入独立主题文件；当前companion_display.json保留玩家亮度、字号等偏好。主题描述负责默认外观，玩家偏好覆盖对应项，空间定义负责安全区域，三者职责明确、不互相覆盖。

## 5. 审阅通过后的实施顺序

1. 先实现陪伴主画面、字幕、输入和左侧临时菜单；交付截图对照，再根据反馈微调。
2. 同一套组件应用到日记、MomoTalk、音乐、空间及人物设定。
3. 整理设置、Home与桌宠气泡，统一语义状态和操作反馈。
4. 定向回归输入法、草稿、分句字幕、语音转文字、触摸、BGM、资源切换、记忆连续和备份恢复；确认新主题仍可回到原版显示。

每批记录改动和checkpoint；不改动已封存V1包。视觉方案审批不代表提前启动Phase8/9保留功能，实际代码修改等用户确认后开始。

本方案用ui-ux-pro-max技能辅助层级、对比度、动效与命中区域检查；没有采用其网页营销布局、外部字体、夸大参与率或新技术栈建议。Unity架构、总宪法和用户授权范围优先。
