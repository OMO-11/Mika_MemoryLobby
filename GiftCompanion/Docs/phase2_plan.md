# Phase 2：Shared Memory 阶段方案

2026-10-13。状态：**用户已批准；2C 暂停后经用户明确恢复，2A → 2E 全部完成并通过技术验收**。依据《项目总宪法》第 21—27、40、49、51 节及 Phase 1 基础。以下保留批准时的方案；实际结果见 `phase2_status.md`，交付入口见 `phase2_delivery.md`，2C 历史暂停记录见 `phase2_checkpoint.md`。Spine 过曝继续留到 Phase 3 视觉对齐。

## 阶段目标与现有基础

让同一个角色在 Companion 和 AgentPet 中记得用户明确说过的事情，退出重开仍保留；允许事实更新、事情完成与主动遗忘，并能追溯到原始消息。

主验收路径为：**Companion 告诉角色事实 A → Home → AgentPet 询问 A → 正确回忆**。增加反向切换和关闭重开，验证共享的是同一份记忆，而非两个模式分别保存。

当前已经具备唯一 AppRoot / CharacterCore / CharacterState、正式 SQLite `memory.db`、串行事务、版本化迁移、共享 LLMService、DeepSeek Streaming，以及模式切换 / 请求取消 / 退出保存。schema v1 只有 `app_state`，MemoryService 仍是不可用占位，尚无正式消息表、长期记忆或上下文检索。Phase 0 的 FTS5 探针通过不能代替本阶段业务验收。

继续使用 Unity 6000.3.7f1、Built-in / Gamma / D3D11、SQLite 3.54.0 和 `deepseek-flash`。Core 保持纯 C#，复用现有 JSON 与原生 SQLite 依赖，不新增 ORM、Embedding、向量库或 RAG 框架。身份与关系配置保持只读；未填写的人设不代为编造。

## 记忆如何分工

| 层次 | 保存内容 | 使用规则 |
| --- | --- | --- |
| Raw Messages | 用户原文与完整角色回复、来源、时间、会话和请求关联 | 保留原文作为来源，不被摘要覆盖；失败 / 取消状态可区分，不将截断片段标成完整回复 |
| Recent Context | 最近已完成的对话轮次 | 跨模式共享、有数量与长度上限，切换不清空 |
| Event Memory | 明确发生的事件、共同经历 | 必须引用原始消息，不保存模型猜测 |
| Stable Facts | 用户明确陈述的偏好与稳定事实 | 活跃版本参与回答，纠错保留旧版本 |
| Open Loops | 用户明确提出的待办、约定与未完成事项 | 只有明确证据才创建 / 解决，不自动启动桌面工具 |
| Session Summary | 当前会话的事件、变化、话题与未完成事项 | 有覆盖范围和来源，压缩上下文，不覆盖原文 |

记忆表示“用户曾明确告诉角色什么”，不将其自动认证为外部世界的客观事实。角色的安慰、推断或虚构经历不能成为用户事实。

## 执行顺序与检查点

### 2A：原始消息、会话与安全迁移

先确保每轮对话可以可靠保存，不接入自动记忆提取。

- 从 schema v1 升级，拟定 v2 增加 `sessions`、`messages`，保留现有 `app_state`。消息保留宪法要求的 id、session_id、role、content、source、created_at，补充 request_id、轮次状态和后续提取状态；会话保留模式、开始 / 结束时间和摘要覆盖位置。最终字段在本检查点设计记录中固定。
- 一次模式停留中的首条受理消息开始会话，返回 Home 或退出时结束；纯素材浏览不制造空会话。重启将未正常结束的旧会话标为中断，新输入开启新会话。来源固定为 `companion` / `agent_pet`，不据此隔离记忆。时间统一存 UTC，涉及“今天 / 昨天”的上下文提供明确的本地日期。
- 通过 CharacterCore 受理有效输入后，先保存用户消息，再发起云请求；忙碌、暂停、无 Key 等未受理提交不制造成功轮次。用户消息保存失败则停止该次云调用，明确返回存储失败。
- 收到完整 `[DONE]` 后，将完整 assistant 消息、轮次完成状态、提取待办与 LastInteractionAt 快照在同一事务提交，成功后再更新可见状态 / 返回完成结果。提交前取消不算成功，提交后不撤销已保存的完成记录。
- 云请求失败或取消时保留已提交用户原文及失败状态；未完成的 assistant 片段不进入完整历史、提取或摘要。若回复已生成但最终落库失败，报告存储失败，不能宣称“已记住”。异常收尾不依赖已销毁场景。
- request_id 和必要唯一约束保证同一轮重入不重复写入。恢复后能够识别中断轮次，不自动重发对话请求。
- 延用迁移前原生备份、事务、参数绑定及更高版本拒绝规则。验收只使用隔离 Validation 库；不导入 Phase 0 探针数据，也不更改现有 Secrets。

**检查点：** v1 状态无损升级；中日文 / emoji 原文关闭重开一致；来源和轮次配对正确；取消、截断、重复完成及落库失败没有伪造成功记录；迁移失败不半升级。

### 2B：后台提取、稳定事实与未完成事项

在可追溯的原文之上建立 MemoryService。

- 拟定 schema v3 增加 `memories`、`user_facts`、`open_loops` 及必要的来源关联与索引。保留宪法字段，事实新旧版本用 `superseded_by` 关联；Open Loop 也补充来源消息与更新时间。`audio_records` 的契约保留，实际建表 / 关联音频留到 Phase 4 迁移。
- 每轮完整回复落库后提交一项提取任务，主要输入固定为本轮 user + assistant，并携带可核对的消息 ID；解决已有 Open Loop 时仅提供有限的活跃候选 ID。取消 / 失败轮次不触发提取。
- 扩展共享 LLMService，增加提取和后续摘要入口，继续复用同一模型、Key、HTTP 生命周期、取消与超时。提取使用低输出预算的 JSON，顶层固定为 `memories`、`facts`、`open_loops`、`resolved_loops`；严格校验类型、长度、范围、来源 ID 与证据，非法结果不落库，不把自然语言回复当结构化结果解析成功。
- 用户事实必须有用户消息证据。模型不能把 assistant 自己说的话、推测或人设写成用户事实。相同事实归一化去重；同一明确事实键发生变化时，事务内将旧记录置为 `superseded`、新记录置为 `active`，保留历史。模糊或矛盾陈述不强行覆盖已有事实。
- 明确的待办 / 约定创建 Open Loop；明确完成或取消时才按候选 ID 解决。暂不执行事项、不主动提醒、不连接 Agent Tools。
- MemoryWriteQueue 的写入职责复用 DatabaseService 已有串行执行队列；不另开竞争写连接。网络请求在队列之外完成，只有校验后的短事务进入数据库队列。
- 提取不阻塞当前回答，也不等待云端结果才允许返回 Home。后台任务属于共享 MemoryService 和应用生命周期，记录原始模式 / 会话，不持有场景对象。前台对话优先；后台云请求最多一个，新的后台调用让位于前台，必要时取消后保留待办。
- 待办和处理进度持久化，内存只保留有界调度状态。重新启动能识别未完成任务；不无限自动重试、不自动重放整个历史。失败保留可重试状态，通过开发入口显式重试，写入按来源轮次去重。

**检查点：** 完整回复只产生一份有效提取；无明确事实可输出空数组；重复任务不重复保存；虚构事实、非法 JSON、未知来源 / 事项 ID 被拒绝；提取失败不破坏已完成对话，也不卡住切换。

### 2C：FTS5 检索与 PromptBuilder

让共享记忆真正影响下一轮回答，而不把整个数据库发送给模型。

- 建立 / 验证 FTS5 索引与源表一致性，默认检索仅 `active` 记忆；更新、纠错、遗忘同步处理索引和过滤。先在实际内置 SQLite 上用自然中文、日文、短词、标点验证分词方案，再固定内置 tokenizer 与查询构造规则；不能只凭 Phase 0 的单词搜索认定中文可用。
- 查询参数绑定，限制候选数量和查询长度，用户标点不能直接成为任意 FTS 表达式。无法匹配时使用有限的结构化事实、近期上下文与明确的无结果反馈，不凭空补全记忆。
- 评分按宪法保留：`FTS relevance × 0.60 + importance × 0.25 + recency × 0.15`。各项先转换到可比较的 0—1 范围，尤其不能直接将原始 FTS 排名值和重要度相加；归一化、时间衰减和并列排序在此检查点固定并做可重复验证。
- PromptBuilder 固定顺序：Identity → Relationship → Active Stable Facts → Top Relevant Memories → Active Open Loops → Current Session Summary → Recent Messages → Current User Message。历史保持 user / assistant 角色与轮次，不拼成一大段当前用户输入；当前消息只出现一次。
- 首版可调整上限建议：稳定事实最多 20 条、相关事件最多 5 条、未完成事项最多 5 条、近期完整对话最多 6 轮、摘要最多 1,000 字符；总上下文字符预算初设 12,000，身份与当前消息优先保留，其他部分确定性裁剪。这些是字符限制，不宣称等同于精确 Token 数；超长单条输入明确拒绝并提示缩短。
- 事实、事件与历史属于带来源的数据，不能提升为修改身份或执行工具的指令。无证据时允许回答“不记得 / 你还没有告诉我”，不让角色装作记住。
- 两种模式调用同一 Retriever / PromptBuilder。用户刚收到完整回复就切换时，尚未提取的内容通过受限的跨会话 Recent Context 进入下一轮，不能要求用户等待提取完成才记得上一句话。来源只作内部追溯，不让角色说“桌宠数据库里记录了”。

**检查点：** 可控数据下评分和预算稳定；自然中文 / 日文能够检索；当前输入无重复；两个模式组装相同事实；提取未完成时最近完整对话仍可跨模式使用；不存在整库注入或过期版本泄漏。

### 2D：摘要、纠错与真正的遗忘

补齐长期运行后最容易出现的旧事实回流问题。

- 离开当前模式、会话累计内容超过长度阈值、或距上次摘要积累较多新消息时，提交后台摘要任务。首版阈值建议为自上次覆盖后新增 10 个完整轮次或 8,000 字符；每个会话合并重复触发。退出只等待本地会话状态提交，不等云端摘要。
- 摘要记录覆盖至哪个消息 ID / 轮次、生成版本和来源。内容只概括事件、重要变化、最近话题与未完成事项；失败保留原文，下一轮回退受限近期上下文，不以摘要替换消息。
- 验证明确纠错的完整链路：旧事实变为 `superseded`，新事实为 `active`，相关事件 / 事项保持一致，后续上下文不能仍把旧值作为现状。已有摘要受影响时失效 / 重建，近期原文中的旧值需明确标为历史，不能覆盖新事实。
- 提供 Core 的显式遗忘接口。开发验收入口按确定的记忆 / 事实 / 事项 ID 操作；“不要记这个”关联当前明确轮次，“忘掉那件事”有多个候选时先确认对象，不能让模型随意扩大范围。完整自然语言交互呈现留给 Phase 3 / 5。
- 遗忘将对应记录置为 `forgotten`，保留历史原文，和未来删除 MomoTalk 记录分开。原始消息 ID 可关联多条独立事实，使用最小来源关联定位范围；首版若无法可靠分离同一消息中的目标片段，则整条相关消息从模型上下文排除，其他活跃结构化事实仍可使用。
- 遗忘同步排除 Retriever、FTS 结果、Recent Context、摘要及待处理提取的相关来源；需要时连同依赖该事实的 assistant 复述一起排除。受影响摘要失效，重建只使用允许的来源；来源不明时保守弃用摘要，不把原文全部重新塞进提示词。
- 写入前检查遗忘 / 纠错版本，已在运行的旧提取或旧摘要不能恢复被遗忘的内容。默认不重新提取被排除的旧来源；再次记住需要用户新的明确授权 / 陈述。完成后清理上下文缓存，下一次请求按新版本构建。

**检查点：** 纠错后只用新值回答；忘记后相关内容不再进入任何后续模型上下文；待处理旧任务不会复活旧记忆；原始聊天仍保留；摘要失败不丢原文，返回 Home 不等待摘要网络请求。

### 2E：真实跨模式与重启验收

先完成离线确定性验证，再做必要的少量真实 DeepSeek 请求。

| 验收场景 | 通过条件 |
| --- | --- |
| Companion → AgentPet | Companion 提供新生成的事实 A，返回 Home 后在 AgentPet 用不泄露答案的问题询问，正确回忆 |
| AgentPet → Companion | 反向提供事实 B，Companion 能回忆；来源和原始消息可追溯 |
| 立即切换 | 完整回复后提取尚未完成就切换，最近对话仍可用，无旧场景回调 |
| 长期检索 | 将 A 移出近期上下文窗口，再提问，证明命中长期记忆而非只靠上一轮文本 |
| 退出重开 | 正常关闭，重开仍先到 Home；进入任一模式可回忆已保存事实 |
| 纠错与遗忘 | 新事实替代旧值；遗忘后构造的模型请求不含被排除内容，旧后台任务无法恢复它 |
| 未完成事项 | 明确创建 / 完成事项，状态和后续上下文一致，不执行桌面操作 |
| 空记忆与故障 | 没说过的事实不捏造；无 Key 可读取本地已有记录 / 浏览素材；JSON、网络、存储与取消故障均有明确结果 |
| 阶段回归 | 唯一 Core / State / Database、Home 中转、退出收尾、透明桌宠及普通窗口恢复没有退化 |

正式聊天 UI 尚未实现，使用显式启用的开发输入 / 验收入口调用 CharacterCore，覆盖两个来源；入口在普通启动时关闭，支持收起，不把技术面板做成正式主画面，也不提前实现最终桌宠快捷键。

EditMode 重点覆盖迁移、事务、幂等、状态过滤、CJK 检索、预算与纠错 / 遗忘竞态；少量 PlayMode 验证场景切换与后台任务生命周期。真实联网仅验证成功链，错误分支用可控响应。Windows EXE 使用 Validation 隔离库，不覆盖真实用户对话。

证据拟归档至 `Docs/Validation/Phase2/`：测试 XML、数据库迁移记录、脱敏跨模式 / 重启报告、构建结果与阶段验收摘要。报告记录来源 ID、状态、计数、耗时和通过条件，不保存 Key、请求头或完整聊天；原始内容只保存在对应隔离数据库中供本地核对。

Phase 2 最终交付原始历史、共享长期记忆与上下文构建能力。正式 Companion 输入 / 字幕 / MomoTalk、表现状态机、八情绪映射和 BGM 留到 Phase 3；VoiceService 与音频队列留到 Phase 4；桌宠正式输入 / 快捷键与 Agent Tools 留到 Phase 5。自动主动提醒、复杂情感推断和新的桌面权限不在本阶段范围内。
