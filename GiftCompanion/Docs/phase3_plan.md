# Phase 3：Companion 阶段方案

2026-10-13 制定，2026-10-14 用户批准实施，并在短暂停后明确恢复。现已按 3A—3E 完成初版开发与技术验收，交付见 `phase3_delivery.md`，人工体验待用户确认；暂停历史保留在 `phase3_checkpoint.md`。以下保留阶段设计与验收条件。本方案依据《项目总宪法》第 5、7—14、18—20、42—47、49、51 节，以及当前工程和素材交接清单制定。

## 目标与已确认方向

把已验收的共享角色核心、对话与记忆接入完整 Spine 陪伴空间。打开后首先看到角色所在的记忆大厅；输入、菜单、历史与设置仅在需要时出现。这个阶段先完成文字陪伴闭环，正式语音留到 Phase 4。

本轮用户明确：

- 人物按 **Mika 与老师的原作关系基调**设计，角色称呼用户为“老师”。后续整理只读人设草案供审阅，不虚构双方已经发生的私人经历，不预设超出原作关系的承诺。
- 允许小幅调整原大厅构图与界面布局，以角色、背景完整性及阅读舒适度为准。
- **BGM 先保留空播放列表，稍后提供素材。** 先实现播放能力，正常运行保持静音。

## 执行顺序与检查点

### 3A：视觉基线、角色配置与资源映射

先明确画面及可用表现，不把后续功能建立在猜测的动画名称上。

- 在主工程保存现状截图，排查用户反馈的 Spine 过曝：核对运行时 Shader、Straight Alpha / PMA、纹理采样、材质与骨架颜色、相机及叠加渲染。依据实测定位，记录修改前后截图和具体差异；不预先归因，也不通过切换 URP 或全局颜色空间掩盖问题。
- 保留完整骨架的背景、角色、绘制顺序与动态。允许微调相机和 UI 安全区；以当前 1280×720 窗口为基线，检查窗口缩放和现有 150% DPI 环境。构图变化后重新核对头部命中坐标。
- 整理 Mika / 老师的人设与 Home 中文文案草案。只读 Identity、Relationship 与行为边界分开记录；原作的具体背景和口吻在需要时查证来源，用户真实经历只能来自实际对话。先完成基础称呼与语气，不扩展好感度或养成系统。
- 选用可随应用分发的中文 TMP 字体，登记来源与许可，验证中文、英文、标点和换行。现有系统雅黑仅用于开发面板，不能直接当作正式打包字体来源。
- 扩展现有 `character_manifest.json` / `expression_map.json`，作为业务映射的明确配置入口；实际附件和局部行为继续引用经过核对的 Behavior Profile，避免复制两套互相冲突的资源真相。
- 固定 neutral、happy、shy、concern、sad、surprised、annoyed、sleepy 八种语义。逐项登记实际表现、是否支持及 fallback；缺失者回 neutral，缺失动作回 Idle，未知协议 action 回 none。Thinking 的 happy / concern 变体不足时共用 Neutral Thinking。
- 原作共有 52 个动画，但不全部开放给模型。现有三个 pat 预设仍属于触摸局部反馈，不能直接改名充当完整八情绪。若从现有附件整理新的持久表情，须单独验证过渡、眨眼、触摸和将来的嘴部控制兼容性。
- 只把已验证、不会破坏场景背景或抢占嘴部的逻辑动作加入白名单；`greet` 等名称只有真实映射通过后才允许。若暂时没有合适动作，白名单先仅有 none，明确登记资源缺口。

**检查点：** 过曝有可复查的排查记录与前后画面；中文阅读正常；八情绪各有实际映射或明确回退；不再将未经验证的动作视为可用。整体视觉和人设口吻在阶段交付时由用户审阅，技术测试不替代观感验收。

### 3B：META 流式协议与共享核心衔接

严格沿用宪法的“首行控制头 + 普通正文”，不把整段回复包装成 JSON。

```text
<META emotion="happy" action="none">
老师，今天过得怎么样？
```

- 在纯 C# Core 内实现有界增量解析器，复用现有 SSE 传输。只处理回复起始处的 META；控制头可能跨任意片段，正文可能与控制头同时到达。头部缓存拟定不超过 256 字符，异常不得无限等待或卡住字幕。
- 缺失 / 非法头、未知 emotion / action 均降级为 neutral / none，正文继续显示；正文中类似标签不再执行。覆盖 CRLF、空正文、未闭合头、超长头、截断和取消。识别出的控制信息不出现在字幕、历史正文或未来 TTS 输入中。
- Core 向表现层提供受限的元信息、正文增量与最终结果，保留 request_id。LLMService 仍只负责网络传输，不引用 Unity；不另建 HTTP 客户端。Companion 请求才要求 META，AgentPet 文字入口保持兼容，记忆提取 / 摘要仍使用原来的 JSON 协议。
- META 和实际动作白名单纳入系统提示，并计入现有 12,000 字符预算。白名单从已验证 Manifest 生成，模型不接触骨骼、资源路径和内部过渡动画。
- **保留原始回复与展示正文的区别。** 拟定 schema v7：`messages.content` 继续保存完整模型原文；增加以 assistant message_id 为键的 `assistant_presentations`，保存 protocol_version、body_text、emotion、action。正文是解析得到的自然语言投影，不是另一次模型改写。最终字段及迁移在本检查点固定。
- 完整回复、表现记录、短期状态和提取待办在同一事务提交；原始消息 ID、上下文版本、消息 / 记忆记录两级引用继续保留。失败或取消只保留已受理的用户原文及状态，不将字幕片段写成已完成回复。
- 新回复的 MomoTalk、近期上下文、提取和摘要读取正文投影，来源仍对应原始消息。schema v6 历史没有协议标记，按普通正文兼容读取，不猜测、不批量删标签、不改写旧原文。后台任务在升级后同样使用此读取规则。
- META 情绪可先作为本轮临时视觉反馈；共享 Mood 在完整回复持久化成功后才更新。取消、截断或存储失败撤销临时表现，不把失败轮次的情绪当作已保存状态。

**检查点：** 任意分片不丢正文、不泄露控制头；非法 META 不打断自然回复；v6 → v7 备份 / 升级保留历史与来源；完整提交、取消及旧数据读取正确；既有跨模式记忆、纠错 / 遗忘和预算约束继续通过。

### 3C：状态机与沉浸式文字交互

建立最小完整链：进入大厅 → Enter 输入 → Thinking → 流式字幕与情绪反馈 → 回到 Idle。

- 实现 `ICompanionVisualController` 的 SetState / SetEmotion / PlayAction，具体 Spine 名称只在映射和 Adapter 内解析。复用已交付的本地表现组件，避免逐帧重启 Idle、直接播放整段原作对白动画或建立第二个表情写入者。
- 状态包含 Idle、Listening、Thinking、Speaking、Touched、SpecialAction、MomoTalk、Menu；情绪独立。对话进度、面板状态和触摸反馈分别保存，由一个场景宿主计算当前表现，防止关闭菜单或摸头退场后错误重置为 Idle。
- Enter 在空闲画面淡入输入并聚焦；再次 Enter 发送有效内容后隐藏。中文输入法组合期间 Enter 仅确认选词，不误发；Shift+Enter 换行。空白不发、重复提交去重，发送失败保留草稿。Esc 先关闭当前输入 / 子面板，再按层级返回菜单或大厅。
- 用户发送新消息时，场景控制器取消旧轮并等待 Core 收尾，再受理新轮；仅保留一个待提交草稿，不堆积自动发送队列。Core 仍只允许一个前台请求。旧轮 request_id 的迟到回调不得覆盖新字幕、情绪或动作。
- 等待首个正文时立即 Thinking，不显示“请求中”“生成中”或 HTTP 状态。Phase 3 无语音：首个正文到达后进入文字呈现的 Speaking，显示对应情绪 / 安全动作；嘴部保持静态，不用字符速率或 BGM 假造语音口型。Phase 4 再以真实音频就绪 / 播放事件驱动 Speaking 和嘴部。
- 字幕下方居中、可读背景、轻淡入淡出；流式更新不重置动画。长回复按可读段落 / 页展示，保留完整正文供 MomoTalk 查看；文本阅读窗口结束后延迟淡出，不因生成结束立即消失，也不把全文塞进越界文本框。具体字号和停留时间在场景预览中调整。
- 正常画面保留完整大厅与低干扰 HH:mm 时钟。现有常驻 Return Home 等骨架按钮收进 Esc 菜单，菜单提供 MomoTalk、设置、返回 Home、退出。
- 头部点击 / 持续摸头复用真实网格和现有手势。UI 接管、失焦、场景退出时取消捕获；点击面板不能穿透成摸头。触摸只覆盖局部视觉，不取消 LLM，结束后恢复仍有效的对话表现。身体 / Special 无已验收区域时不虚构命中范围。
- 菜单或历史打开不隐式取消正在进行的对话；关闭后恢复正确进度。返回 Home / 退出才按已有生命周期取消、保存、释放。网络 / Key / 存储失败只显示简短自然反馈，详细原因进入诊断日志；本地错误提示不冒充成功角色回复或触发记忆提取。

**检查点：** 中文输入法无误发送；新消息可替换旧轮且无迟到污染；字幕与头部互动兼容；UI 不穿透、失焦不残留；打开 / 关闭面板及返回 Home 后状态正确。未配置 Key 时仍可进入大厅、互动、查看本地历史。

### 3D：MomoTalk、设置与 BGM

把历史和设置收进临时面板，主画面继续以场景为中心。

- MomoTalk 从 Esc 进入，只作历史查看，不增加第二个常驻发送框。读取两个模式共享历史，以同一个角色身份呈现；展示本地时间与完整自然语言正文，明确区分中断 / 失败的用户轮次，不伪造 assistant 内容。
- 新增纯 C# 历史读取服务，经现有 DatabaseService 单连接队列查询；UI 不直接读 SQLite。采用稳定游标分批加载，拟定每批 30 轮，用时间与 ID 处理同时间记录，避免重复、漏页或一次加载整库。当前 LoadTurnsAsync 的有限最近窗口不能充当全部历史分页。
- 对富文本标记作显示层转义，不能让用户 / 模型正文控制 TMP 标签；不修改数据库原文。关闭面板取消旧查询，不能在已销毁场景继续更新 UI。
- 保留 Phase 2 的明确对象遗忘：历史轮次可选“不记住这一轮”，设置中的简洁记忆列表可按明确记录移除。调用 Core 既有接口，并说明这影响未来回忆、原始历史仍保留；不把关闭面板或隐藏聊天当作遗忘，不在本阶段增加自然语言对象消歧系统。
- Phase 3 尚无正式音频缓存，复听按钮保持不可用，不重新调用 GPT-SoVITS。`audio_records`、缓存失效治理和真实 Replay 留到 Phase 4。
- 设置面板先提供 BGM 音量 / 静音、字幕文字大小及记忆入口，保存到非秘密设置；保留既有字段和损坏配置恢复规则。API Key、endpoint、模型参数和技术诊断不进入普通菜单。
- 实现场景所属 BgmManager：有限播放列表、循环、淡入 / 淡出、音量 / 静音、切歌与释放。无素材、路径缺失或解码失败均安全静音，错误只记日志；退出 Companion 淡出并释放，不进入 AgentPet 后继续播放。
- 用户尚未提供 BGM，`bgmPlaylist` 保持空。用隔离的合成音频验证循环与音量能力，测试音频不进入正式包；不把已交付的游戏台词当 BGM。正式曲目听感验收在用户提供素材后补做。
- 此处预留真实语音播放事件的简单接点；BGM Ducking 的策略、优先级和实测属于 Phase 4，不用文字生成状态假冒正在播放语音。

**检查点：** 跨模式历史分页 / 重开正确；META 不显示；遗忘后历史仍在但未来上下文排除；设置重开保持；空 BGM 列表静音无报错，测试音乐循环和淡出正确，离开模式无残留 AudioSource。

### 3E：集成回归与 Windows 交付

- 核心单元测试集中覆盖 META 分片 / 降级、原文与正文投影、迁移事务、游标分页和新旧轮取消；不为简单映射或文案堆砌测试。少量 PlayMode 验证状态 / UI 接管 / 场景清理，继续运行既有核心与素材回归。
- 真实 DeepSeek 验证 META + 正文流式输出、已开放情绪 / 动作、跨模式回忆与无 Key 退化；只在 Validation 隔离库中使用合成事实，不把私人历史用作验收素材。
- Windows 干净构建至 `Builds/Phase3/`，要求零构建错误。实测大厅文字输入、替换旧轮、MomoTalk、重启、窗口缩放，以及 Home → Companion → Home → AgentPet → Home 唯一 Core / State 和透明窗口恢复。
- 保存应用客户区截图，比较过曝处理、构图、中文字幕、菜单和历史画面。报告记录测试结果、版本、耗时、构建体积、来源哈希与限制，不包含 Key、完整对话或桌面其他窗口内容。
- 不覆盖 Phase 2 证据。拟新增 `Validation/Phase3/`、阶段测试 / 构建入口和 `phase3_delivery.md`；同步架构、角色 / 记忆协议、README、状态与开发日志。

**技术通过条件：** 上述自动 / 实机检查通过，原有记忆和窗口链无回归，无重复服务、输入捕获或旧请求残留。

**人工通过条件：** 用户确认画面首先像记忆大厅，过曝明显改善且场景完整，Mika / 老师称呼与语气合适，中文输入 / 字幕 / 触摸舒适，菜单和 MomoTalk 不干扰平时陪伴。空 BGM 列表静音属于已确认边界，不将缺少曲目误报为音乐听感通过。

## 阶段交付与后续边界

交付为可进行正式文字陪伴的 Windows 程序、可审阅的只读角色配置与资源映射、分段进度日志及验收证据。Phase 2 开发面板继续隐藏，仅显式诊断入口可用，不承担产品操作流程。

Phase 4 再实现 VoiceRuntimeManager、SpeechSegmenter、TTS / Audio Queue、实际音频驱动口型、BGM Ducking、缓存和历史复听；本阶段不启动 / 复制第二份 GPT-SoVITS，也不改变已确认的中文默认语音。Phase 5 再做 AgentPet 最终输入、拖动、全局热键、工具和权限。最终打包精简、跨机分发及全面多屏验证属于 Phase 6。

原始 `Material/`、冻结的 CHDDD V7 和用户正在制作的 Blender 文件不自动改写 / 重导。Unity、Runtime 和 API 模型维持当前基线；本阶段的视觉修改限于主工程中的可追踪配置和必要适配。

按 **3A → 3B → 3C → 3D → 3E** 逐项实现，每项完成先验证、再写日志和状态。资源不足或视觉 / 人设需要选择时提供具体候选与效果再对齐。当前初版实现与技术验收已完成，等待用户体验及细节精修，不提前进入 Phase 4。
