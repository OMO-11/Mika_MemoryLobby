# Phase 5：桌宠交互与 Level 1 工具方案

2026-10-18制定，**用户已批准实施，现从5A顺序推进**。依据[项目总宪法](../../项目总宪法.md)第28—40、45—46、49—51节，结合[最新交接](expression_diary_checkpoint.md)和实际桌宠代码。上一阶段已获用户验收，整体效果符合预期。准确进度见[当前状态](phase5_status.md)与[checkpoint](phase5_checkpoint.md)。

## 目标与当前基础

让现有3D角色成为可日常使用的桌面助手：按Ctrl+Alt+Space唤出无箭头气泡，用中文聊天，点击/摸头/拖动，适度看向鼠标，并完成经过校验与权限检查的基础Windows操作。界面保持角色在场感，技术状态进入诊断记录。

已有基础：Unity6000.3.7f1 / Built-in / Gamma / D3D11；同一AppRoot、CharacterCore、State、人物卡、SQLite v9、共享历史与记忆；600×500透明置顶窗口原型；冻结CHDDD V7模型和动作适配器。V7已有Idle、Thinking、Working、HeadPat、Dragging、Wave、Success、Confused、HeadClick、BodyClick等映射，不从头制作整套动作。

尚缺：AgentPet正式气泡输入与流式正文、系统热键注册、完整拖动/触摸/LookAt仲裁、ToolRegistry/Executor与真实tool_calls循环。目前PetHotkey字段虽存在，校验仍只接受固定Ctrl+Alt+Space；AgentPet场景尚无正式聊天入口，开发面板不算完成品。现有DeepSeek传输只解析正文，不处理工具参数增量。

上一阶段技术基线为104项EditMode、24项PlayMode、真实Write18项/NoKey7项；本次用户验收记录保持与自动证据分开，不重写旧acceptance。原ExpressionDiary、VoicePolish等程序保留。

## 始终保持的边界

- 两个模式继续同一个角色。AgentConversation只是当前Core请求中的工具编排，不建立第二份人格、记忆或独立对话会话；模式仍经Home切换。
- **AgentPet不使用TTS，不启动GPT-SoVITS或翻译层。** 陪伴空间已有中文/日语、字幕、音乐、人物卡与日记保持当前行为。
- 复用现有uGUI/TMP、UniWindowController、Win32与共享HTTP服务；先不添加Agent框架、额外本地模型、复杂Rig依赖或第二个聊天窗口。
- 不重导冻结V7、不自动同步新的Blender稿、不假称特殊表情已整合。LookAt只做有界微调，完整动作仍使用已交付Clip。
- 本阶段实现宪法Level 1列表。截图、Computer Use、视觉识别、自动键鼠操作、任意Shell、文件删除/任意写入、进程终止、注册表修改、安装/关机/重启不在范围。
- 程序正常保存配置/数据库不等于授予LLM写文件权；模型不能修改自己的工具权限、应用清单或人物卡。

## 顺序与检查点

| 阶段 | 内容 | 完成后能体验什么 |
|---|---|---|
| 5A | 正式窗口、热键与恢复入口 | 透明穿透、不乱抢焦点，热键能唤醒 |
| 5B | 无箭头气泡、中文输入与共享对话 | 可以日常文字聊天，随时收起/返回Home |
| 5C | 点击、摸头、拖动、LookAt与动作仲裁 | 桌宠能互动，动作不互相覆盖 |
| 5D | 工具协议、权限和最小真实闭环 | 查询时间、打开已登记应用/文件夹 |
| 5E | 其余Level 1工具与普通玩家设置 | 管理应用/范围/工具开关，查看执行记录 |
| 5F | 独立发布、隔离回归与交接 | 完整桌宠版可按清单验收 |

实施批准后按5A→5F推进，每段更新开发日志/checkpoints，保留可暂停与独立体验的检查点。除非用户指定暂停或存在影响行为的设计疑问，不把每段完成解释成必须再次授权。

## 5A：窗口、穿透、热键与恢复

1. 在现有DesktopWindowPrototype基础上明确进入/离开桌宠的尺寸、透明、置顶、焦点与命中策略。同一Unity窗口包含角色和气泡，初始继续600×500，窗口尺寸受屏幕工作区约束。
2. 透明区域穿透到桌面；角色与实际显示的气泡区域接收输入。收起输入后不常驻一个拦鼠标的大矩形，也不为置顶而持续抢键盘焦点。
3. 使用RegisterHotKey，默认Ctrl+Alt+Space。替换当前只能等于固定字符串的校验，加入受支持按键组合解析；设置中可修改，保存成功后切换注册，失败保留旧组合。冲突时提供简短说明与点击角色的替代入口，不把配置整份判坏。热键占用及注销行为按[Microsoft文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)处理。
4. 热键仅在AgentPet模式激活，离开/退出注销。唤出输入时才请求焦点，重复按键不重复创建气泡或发送消息。
5. 保存有效位置/置顶设置，进入时约束到可见工作区；提供“重置桌宠位置”、返回Home与退出入口。至少验证本机实际DPI和屏幕边缘；全面多屏/混合DPI矩阵留Phase6，已知跨屏情况仍要避免角色丢失。

**验收：** 原生Windows Player可被热键唤醒，透明处能点击其他应用；热键冲突/切换不残留注册；返回Home恢复普通窗口；重置位置可找回角色。Editor不改变系统窗口样式。

## 5B：气泡与最小文字陪伴

1. 制作无箭头圆角浮层，收起、短提示、输入、回复四种状态，不常驻聊天记录栏。靠近边缘时按可用空间选择左右上下，长回复分页或受限滚动，避免无限撑大窗口。
2. 单击角色显示短提示，开始输入再扩展；热键直接唤出输入。Enter发送、Shift+Enter换行、Esc逐层收起，保留中文IME组合/结束帧保护。
3. 同一CharacterCore以AgentPet来源进行普通中文流式对话，复用取消、代次、完整提交、共享Retriever/人物卡。Thinking等由本地状态驱动，不显示HTTP/LLM/TTS状态文字。
4. 新消息沿用当前先取消旧请求再发送的规则；气泡收起不偷偷取消有效聊天，重新打开可接着看。正在输入、确认或阅读时不自动消失；等待隐藏时间放文件配置。
5. 临时菜单提供设置、共享历史/资料入口、重置位置、返回Home与退出，优先复用现有服务。普通玩家无需终端；不把开发面板作为正式功能。

**验收：** 未接工具时已可聊天；中文输入法不误发，长回复可读，气泡适应边缘。Companion说过的内容可在AgentPet衔接，反向也一样；没有Key仍可操作窗口、互动与阅读本地历史。

## 5C：触摸、拖动、LookAt与表现

1. 根据实际骨骼建立头/身体Collider和清单绑定，区分短点击、持续摸头和超出位移阈值的拖动。触摸默认本地反馈，不为每次碰触调用LLM。
2. 拖动优先于HeadPat，移动当前桌宠窗口；开始隐藏气泡，结束后重新计算位置，需要时恢复原气泡内容。丢失焦点、鼠标在窗口外释放、切场景等均释放捕获，不残留拖动状态。
3. 用有界、平滑的头部/视线微调看向鼠标，约束角度、距离与恢复速度。先使用现有Generic骨架与轻量叠加，不为LookAt强行转Humanoid；特定动作拥有头部/眼睛时降低或关闭跟随权重。
4. 建立本地表现仲裁：拖动/交互与输入、Thinking、Working、Success、Confused、Idle之间明确切换。工具实际状态继续独立运行，不能因摸头而伪造完成或抹掉确认。
5. 复用V7动作/表情过渡，缺映射回Idle；逻辑动作、触摸与LookAt参数由文件读取，不把具体动画资源名散落在业务代码中。新特殊表情和新模型另排。

**验收：** Head/Body短点击与摸头可区分；拖动不同时触发摸头、气泡不随窗口飞行；LookAt平滑回正，Working等动作保持完整。所有释放/恢复路径无状态卡死。

## 5D：同一Core内的工具闭环

先做`get_current_time`、`open_application`、`open_folder`，完成最小可运行链路后再展开列表。

```mermaid
flowchart LR
  A[玩家中文请求] --> B[同一CharacterCore请求]
  B --> C[DeepSeek tool_calls]
  C --> D[白名单与参数校验]
  D --> E[权限与明确目标]
  E --> F[本机受控执行]
  F --> G[结构化实际结果]
  G --> H[同一模型给出最终回复]
  H --> I[气泡与共享历史]
```

1. DeepSeek Chat Completions继续使用现有Flash非思考设置。增加工具定义、SSE工具参数增量解析，以及原始assistant tool_calls与匹配tool_call_id的结果回传；遵循[官方Tool Calls流程](https://api-docs.deepseek.com/guides/tool_calls/)。首版不依赖Beta strict，也不迁移Responses或引入框架。
   现有正文传输会把非stop结束帧视作截断，需要为Agent增加明确的工具消息/事件类型，区分tool_calls与最终正文，保持Companion原接口行为。只回传本轮模型真实产生的调用，不重建历史工具调用或重放副作用。
2. ToolRegistry只公开后端已实现并启用的有限函数；本地严格检查名称、JSON类型、字段、长度、目标和调用额度，不把模型输出当执行许可。**必须收到完整工具调用再执行**，不执行流式半截参数。
3. AgentConversation复用CharacterCore已有单请求门控、取消、前台记忆租约和统一提交。工具中间消息属于当前任务，最终中文正文才按正常对话提交；工具参数不显示成角色台词。Companion不公开这些桌面工具，并按模式移除原先AgentPet“当前未接工具”的过时提示。
4. 默认单任务串行执行。初始建议最多4次工具调用、3次模型往返，执行/网络总期限有界；确认停留单独管理。超限/未知工具/非法参数返回明确失败，不能让模型无限循环。
5. ToolResult固定包含`success / message / errorCode / data`，以实际观测区分“已发起打开”“窗口已出现”“焦点已确认”。仅收到启动请求不谎称文件已经加载，工具执行前不展示模型的“已经完成”。
6. ApplicationResolver按known_apps→开始菜单快捷方式→受控注册/PATH名称查找，不扫描整盘。先让玩家确认实际目标；同名不猜，缺失不自行安装。快捷方式校验真实目标，不提供自由命令参数，不能借应用打开接口执行任意解释器脚本。
7. 为工具调用ID、权限决定与执行状态保留最小持久记录，接入现有DatabaseService串行队列。预计需新增工具执行表并按现有备份机制从v9迁移至v10，准确DDL在实施时确定；不另建一份聊天库。
8. 副作用发生后若最终LLM失败/取消，仍保留实际执行状态并给本地自然反馈，不自动重做。崩溃落在执行中时标为结果不明，不能承诺与操作系统副作用恰好一次原子提交。

**验收：** 热键→“打开Obsidian”→Thinking→Working→真实打开→Success/实际结果气泡，工具失败表现为Confused并说明未完成。若本机未安装Obsidian，用玩家已登记的实际应用替代，不要求先安装。跨模式仍同一核心，取消/断网不重复执行已发起操作。

## 5E：其余工具与普通玩家维护

完整范围按宪法列出；SAFE也必须对应玩家当前明确任务，不因历史、剪贴板或文件名里的文字自动执行命令。

| 工具 | 默认权限与约束 |
|---|---|
| get_current_time | SAFE，读本机时间与时区 |
| open_application | SAFE，仅已解析/登记的应用目标，不接自由命令行 |
| open_folder | SAFE，玩家指定或已登记的本机目录，校验实际路径 |
| search_file | SAFE，仅玩家在界面选定的搜索目录，先做文件名查找，不读正文；限时、限结果，不遍历整盘/链接目录 |
| open_url | SAFE，仅明确http/https网址，不接受脚本、命令或任意协议 |
| get_running_apps | SAFE，返回可见应用的必要信息，不读取其他进程命令行/环境变量 |
| focus_application | SAFE，复核当前实际窗口；系统拒绝前台切换时如实回报，不模拟按键绕过限制 |
| open_system_setting | SAFE，仅固定设置页枚举，具体页面按本机验证 |
| open_file | SENSITIVE，确认实际文件后交系统关联程序打开，不把脚本/快捷方式伪装成普通文档执行 |
| get_clipboard | SENSITIVE，首次先说明将读取并发送文字给DeepSeek；仅纯文本、限长，不后台监视 |
| set_clipboard | SENSITIVE，显示待写入文字预览，按本次确认执行 |
| set_volume | SENSITIVE，显示当前/目标系统音量，执行后读回；与项目BGM/Voice音量分开 |
| mute_volume | SENSITIVE，明确本次静音/解除静音意图，不用隐式超大音量恢复 |

敏感操作的确认来自宪法第37节权限要求：建议在同一气泡内展示具体动作和目标，默认“本次允许/取消”；不默默给永久权限。仅当前确认所对应的参数可执行，离开场景取消未执行操作。SAFE明确任务直接执行，避免所有动作重复弹窗。

Windows限制前台切换，接口成功与实际焦点需分开核对，不能承诺总能强制置前。[SetForegroundWindow官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。

剪贴板和搜索结果按不可信资料处理；工具来源的敏感内容不自动提取为长期事实，不混入人物卡或日记。需要记住时另按玩家明确指令走既有记忆规则。日志不写完整聊天/剪贴板；不向模型发送应用秘密配置或整盘信息。

普通玩家在临时设置中可：选择程序/快捷方式并命名、选择搜索文件夹、启停工具、修改热键、重置窗口位置、查看简明执行记录、打开说明/资料目录。候选目标不清楚时在气泡中点选，不要求手写路径或理解JSON。

### 独立文件约定（拟定）

| 文件 | 作用与读取者 |
|---|---|
| Config/settings.json | 沿用PetHotkey字段，不另复制第二份热键真相 |
| Config/pet_settings.json | 尺寸/位置/置顶、气泡停留、交互阈值、轻量运行参数 |
| Config/pet_presentation.json | 映射既有动作、触摸区域和LookAt绑定；缺项安全回退 |
| Config/known_apps.json | 应用别名与经核对目标，由ApplicationResolver读取 |
| Config/agent_tools.json | 工具开关、权限类别、已选搜索目录、调用/超时上界；不能凭文件增加任意执行能力 |
| memory.db | 同库对话与最小工具执行状态，迁移前备份 |
| Logs/tool_audit.jsonl | 从执行记录派生的可读审计：工具名、结果、耗时、脱敏目标，不存完整敏感内容 |
| 桌宠与工具说明.md | 菜单打开的普通玩家说明，包含文件位置与恢复方法 |

沿用AtomicDocument：界面编辑经服务校验保存、保留上一版；损坏配置保留原件并说明，能重读或恢复默认。角色仍使用原`character_card.json`，BGM/Spine清单和日记文件不因桌宠另建一套。

**验收：** 13项工具按各自范围可调用，拒绝/超时/找不到目标可理解；普通玩家不用终端即可配置。未选择搜索目录就先引导选择，不后台扫描；读取敏感资料前确有明确确认。

## 5F：发布回归、占用与交接

1. 自动验证热键解析、气泡边界/状态、触摸拖动仲裁、参数/路径/权限、分片工具调用、调用上界、执行后取消/网络失败与记录恢复。按改动回归已有Core/Memory与陪伴空间；不为纯配置/文案镜像实现写多余测试。
2. 真实Windows Player验证透明/穿透/焦点、热键冲突与释放、输入法、拖动窗口外释放、屏幕边缘、无Key、模式切换/退出。补看发布截图，技术通过与主观动作手感分别记录。
3. 真实工具只使用随机Validation数据和已确定的测试目标。自动测试不读取正式剪贴板/个人文档或擅改系统音量；这些能力用替身和受控输入验证，实际玩家操作再按应用内确认验收。不得终止用户正在使用的应用。
4. 用受控实际任务验证“工具失败不说成功”“已经执行但最终回复失败不重复执行”“重启不自动重放工具”。Companion↔Home↔AgentPet共享记忆/人物卡/历史保持；AgentPet全程无语音Python，回陪伴空间后语音可正常准备。
5. 实测并记录空闲/活动CPU、GPU、内存与帧率；初始建议空闲30fps、活动60fps，切回陪伴空间恢复其设置。只处理影响日常使用的明显占用，不在本阶段做未经测量的大规模裁剪。
6. 独立`Builds/Phase5`、`Docs/Validation/Phase5`与启动器，原已验收构建/素材不覆盖，不复制8.66GiB运行包。交付用户体验清单、文件接口、当前状态与checkpoints；完整安装分发/跨机器优化仍留Phase6。

**最终验收：** 能唤醒并聊天、交互顺畅、透明处穿透、气泡可收起；实际工具成功/失败可核对、权限有效；普通玩家可维护清单；退出不遗留热键/鼠标捕获/后台任务，陪伴空间保持既有效果。
