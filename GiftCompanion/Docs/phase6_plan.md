# Phase 6：集成、资料保护与 V1 交付方案

2026-10-18制定，2026-10-19获授权实施。**用户要求暂缓Phase5玩家测试，继续Phase6；实施进度以[状态](phase6_status.md)为准。** Phase5技术验收证据保留，玩家验收仍待反馈，见[交付](phase5_delivery.md)。依据[项目总宪法](../../项目总宪法.md)第1、40—42、48—51节和已记录的分发/备份/DPI边界制定。

## 目标与范围

把现有陪伴空间与桌宠整合成普通玩家可以长期使用、维护和迁移的V1：拿到完整目录包后双击启动，通过界面配置自己的Key，能备份/恢复资料，遇到错误有可理解的处理入口。共享状态、记忆、音色与工具已有的功能先做集成核对，缺陷按实际修复，不重做一套核心。

当前已具备共享Core/State/Memory、SQLite v10与迁移前原生备份、DPAPI密钥文件、内置双语运行环境、内容清单和资料菜单。尚无正式面向玩家的Key输入向导、完整资料备份/恢复服务与最终独立分发验收；开发启动器仍从工程读取Editor Key、指定共享Runtime路径。运行时本身已有安装根相对路径回退，正式包需实际验证该路径。

Phase5已实际交付schema v10；Phase6以此为集成基线，本次状态同步不实施Phase6数据库改动。Unity/渲染基线继续6000.3.7f1 / Built-in / Gamma / D3D11。

## 6A：集成核对与发布范围冻结

1. 核对唯一AppRoot/CharacterCore、人物卡、State、历史、Memory和数据库连接。两模式切换经Home，取消/保存/释放仍走统一生命周期；AgentPet工具编排不拥有另一份角色记忆。
2. 验证跨模式衔接、人物卡修改、遗忘/纠错、日记来源和工具执行记录。工具来源的敏感内容维持Phase5约定，不因集成而自动变成长期事实。
3. Companion继续既有中文正文→廉价日语本地化→本地TTS、PCM字幕/口型、BGM淡化/单曲循环；AgentPet仍无TTS。退出/切换后的自有模型进程、热键和鼠标捕获都应释放。
4. 汇总各阶段实际支持范围、已验收素材和未适配能力。检查数据版本与包版本兼容性，固定发布候选，不在收口时顺便加入新框架、新模型或大改UI。
5. 建立宪法第50节的“要求→现有实现→验证证据→剩余问题”对照表。已有明确通过且未受影响的结果沿用，新增验证集中在集成边界。

**验收：** 两个模式确实共享同一个角色，状态/文件/退出行为连贯；没有重复服务和遗留活动任务，剩余问题有明确归属。

## 6B：首次使用、配置与故障回退

1. 普通玩家从应用内输入/更新DeepSeek Key，掩码显示，显式保存，可主动测试连接；不再要求运行Configure-DeepSeek.ps1。开发脚本继续保留维护用途，正式包不读取工程Editor Secrets。
2. 沿用当前Windows用户级DPAPI文件，不把Key写进普通JSON、日志、资料检查或发布包。跨Windows账户/机器迁移默认重新输入Key，不依赖直接复制DPAPI密文可用。[Microsoft DPAPI说明](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。
3. 没有Key时仍可进入Home/场景、查看已有资料与缓存，明确说明联网对话需配置；不伪造离线LLM答复。语音不可用时继续文字，日记/工具不可用时按实际结果回退。
4. 在设置/维护页检查必要文件、Runtime健康、目录可写性与版本兼容性；技术原因只在诊断页和日志，主画面保持自然反馈。提供重新读取资料、重试语音、重置桌宠位置等已有或必要的修复入口。
5. 升级保留玩家已选语言、音量、人物卡、歌单、空间与工具配置；新字段按版本补默认，不把每次升级变成重置。损坏配置保留原件，用户可通过界面选择恢复默认或重新导入。

**验收：** 新Windows用户不用终端即可配置和进入应用；无Key、Key错误、断网、缺模型、端口占用均不导致整个程序不可用。普通启动不依赖开发机环境变量。

## 6C：资料备份、恢复与迁移

首版做**玩家主动触发的完整快照恢复**，不做云同步、自动合并两个历史库或持续监视文件。

1. 菜单提供“备份资料”“从备份恢复”“打开资料文件夹”。备份前让当前受控任务收尾，暂停写入并取得一致的数据/配置视图；数据库复用原生SQLite备份能力，不只复制仍在使用的memory.db而漏掉WAL。[SQLite Backup API](https://sqlite.org/backup.html)。
2. 必备范围：数据库、人物卡与其他Config、玩家导入的Content、VoiceReferences和已有日记MD。随包素材记录依赖清单，不复制安装Runtime进每一份备份。外部MD批注作为文件保留，不反向改写数据库正文。
3. 历史AudioCache作为可选项，界面展示大小。精简备份不含缓存时，明确说明恢复后旧文字仍在、部分历史无法复听，禁止悄悄调用TTS补生成。
4. 备份清单包含应用/数据库版本、时间、角色ID、文件相对路径、大小/哈希和是否包含语音；排除Secrets、开发Validation、安装运行环境及诊断包。备份输出到本次选定位置，避免把备份自身再次收进资料包。
5. 恢复先暂存、校验路径/总大小/文件哈希与数据库完整性，核对随包依赖和缺失资源；展示备份时间、范围、当前资料将被替换的后果。确认后先为当前资料留恢复点，再关闭相关连接、切换固定数据集，失败保留原资料或可恢复记录。
6. 不用旧程序读取高版本数据库；允许的升级仍先备份再迁移。恢复不覆盖本机Secrets/Runtime，不替换代码；新机器的应用路径、搜索目录与工具授权重新核对，恢复本身不执行历史工具。
7. 恢复回到备份时刻，包括当时的遗忘/排除状态；这一点必须在预览中说明，不自动恢复旧快照。遗忘当前记录不等于旧备份也已抹除，备份的保留/删除由玩家明确管理，不宣称所有副本自动遗忘。

**验收：** 在隔离数据中完成“新建资料→备份→改变内容→恢复→重启查看”，数据库/配置/导入素材/MD一致。损坏或更高版本备份不覆盖现有资料；不含语音与换机重新配Key的行为可理解。

## 6D：运行包、体积和独立目录

按照宪法提供完整目录，而不是把数GB内容强行塞进单EXE。概念布局如下，实际文件以Unity生成结果为准：

```text
Gift/
  GiftCompanion.exe
  GiftCompanion_Data/
  UnityPlayer.dll
  MonoBleedingEdge/
  Runtime/GPT-SoVITS/
  Licenses/
  Release/release_manifest.json
  README.md
```

1. 第一个目标是可解压/复制程序目录，双击EXE启动。完整包只带一份内置语音Runtime，玩家无需安装Unity、Python、Blender、Git或CUDA Toolkit；显卡驱动和实际硬件仍作为验证条件记录。
2. 所有Runtime/素材引用按安装根或用户资料根解析，不依赖W:工程路径、开发启动器或外部Python。持久资料继续放用户AppData；“程序目录可移动”不等于“复制EXE即可迁移全部资料”，换机走6C。
3. 打包使用明确文件清单，排除Material、Library、Temp、训练原档、Editor/测试程序集、个人Key和测试聊天。保留运行所需原生DLL、资源与许可证/说明；安装目录不能成为隐式个人资料仓库。
4. 在隔离暂存副本分析体积与实际加载，任何裁剪先记录、可回退，再验证中日文/必要音色和正常退出；不直接删除已验收的原Runtime、源模型或用户素材。
5. 当前历史装配体积约8.66GiB，Torch/CUDA等占主要部分；该数字是既有基线，不是最终包大小承诺。默认保留双语，不为体积擅自量化、换推理栈、升级Torch或删中文模型；体积目标依据真实测量决定。
6. 明确安装包解压后的磁盘需求、首次启动耗时、缓存位置和清理入口。运行期写入优先留用户资料/临时目录，验证安装目录权限，不要求常驻管理员模式来绕过错误。
7. 生成版本/文件/哈希清单，记录Unity、Runtime和模型配对。首版优先目录包，安装向导、签名/分发渠道等按真实交付需要另定，不为其引入自动更新系统。

**验收：** 在没有工程路径/Editor Key/开发环境注入的环境中启动，模型从包内加载；复制程序目录后仍工作，玩家数据不丢。只有实际验证过的硬件列为支持，不能以本机通过替代全部显卡兼容。

## 6E：屏幕、兼容、占用与稳定性

1. 将100%/125%/150%/200%缩放、不同分辨率、跨屏/负坐标、混合DPI和显示器断开列为目标矩阵；以实际可获得设备记录通过/未验证。窗口、气泡、命中区和拖动使用一致的坐标约定，避免只改字体而点击偏移。[Microsoft高DPI说明](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows)。
2. 验证最小化/失焦、锁屏/恢复、睡眠唤醒、断网重连、模型异常和退出时机。持续保存与取消不能阻塞界面；异常恢复不接管其他进程，也不重放已执行工具。
3. 记录冷启动、语音预热、首音、空闲/活动CPU/GPU/内存与缓存增长。按实测处理重复加载、未释放对象、无上界队列；不承诺未经测量的固定占用或恒定首音延迟。
4. 至少安排一次连续使用观察及重复模式切换，时长/次数按目标机器确定，建议先用1—2小时观察基线。影响正常使用的卡死、泄漏或资料风险必须在V1候选前处理；更长周期的反馈积累才留Phase9。
5. 只测试受控资料。干净账户/隔离环境能验证配置与路径，但没有GPU的虚拟环境不能代替真实GPU语音验收；目标机不足的条目明确标未验证并说明能力回退。

**验收：** 目标设备可正常读字、点击、拖动和切换，角色可找回；长回复/模型异常后占用能回落，重启后资料连续，支持范围和限制有实测记录。

## 6F：V1候选发布与维护交接

1. 按宪法第50节逐条核对最小功能与真实失败路径，发布版验证独立启动、首次配置、两模式、工具、缓存复听、日记和备份恢复。旧证据未受影响时保留，新包/新代码必须有对应新验证。
2. 输出发布目录、完整文件清单、兼容范围、首次使用说明、常见问题、文件接口、版本历史、已知限制、维护报告与checkpoint。普通玩家完成一次“启动→添加资料→备份→恢复”的试用流程。
3. 手工更新采用明确版本目录和资料兼容检查，不覆盖玩家配置或自动更新。需要回退时检查数据库版本并选择对应快照，不能只换旧EXE再强读新库；回退造成的时间回溯提前展示。
4. 新电脑/新账户先重新配置Key和应用目标，默认不恢复曾经进行中的工具任务。工程与训练原素材由维护者保留，普通玩家包保持可读、可维护。
5. 技术通过和玩家体验分别记录。阻塞缺陷清零、未验证设备清楚标注并经玩家验收后，宣布**V1交付完成**；不要求把可选Phase7—9全部实现。

## 文件与普通玩家入口（拟定）

| 文件/位置 | 作用 |
|---|---|
| 原有Config/*.json | 继续作为歌单/空间/人物卡/声音/桌宠/工具的实际配置，不复制第二套真相 |
| Config/backup_policy.json | 默认备份选项、是否含历史语音；首版手动触发 |
| 备份内backup_manifest.json | 快照时间、版本、范围与哈希，供后端校验 |
| Release/release_manifest.json | 程序/依赖/资源版本与发布文件清单 |
| Secrets/deepseek.key.dpapi | 当前用户Key；不进入普通备份/发布包/诊断 |
| Diary/*.md与原memory.db | 可读回顾与共享记录，继续由服务保持来源关系 |
| 资料检查.md、使用说明.md | 界面可打开的本地维护说明 |

Key设置、备份/恢复、配置重读、缓存管理和诊断导出均提供菜单入口。诊断默认脱敏、无聊天/剪贴板/Key正文，导出前可看范围；资料备份仍属于玩家私人内容，不把备份当可随意分享的诊断文件。

## 本轮边界与后续

现已授权按6A—6F执行。本轮只以隔离资料做技术验证，不恢复或读取玩家正式对话，不覆盖旧构建/验收。首版采用完整目录候选包；未提供的硬件与长时玩家体验如实保留未验证状态。

总宪法正式阶段到6为止。Phase7—9是额外建议，见[后续路线](post_phase6_roadmap.md)，均需按真实需求单独选定，不默认扩大V1范围。
