# Phase 6之后：可选迭代路线

2026-10-18。**路线建议，尚未批准或实施。** 总宪法原有编号止于Phase6；本文的Phase7—9为便于后续讨论提出的编号，不是原手册要求，也不代表必须全部开发。

当前状态（2026-10-23更新）：Phase5和Phase6技术实施结束，旧V1候选保留。按用户批准的[v1完善方案](v1_refinement_plan.md)完成缺陷修补与Phase7有限精修，[新候选已技术交付](v1_refinement_delivery.md)。Phase5玩家测试暂缓、正式玩家验收待反馈；Phase8/9保留项尚未启动。旧交付证据保持原记录，新候选证据在Validation/V1Refinement。

## 总体路线

| 阶段 | 定位 | 启动前提 | 完成标志 |
|---|---|---|---|
| Phase5 | 桌宠与Level 1工具 | 方案获准 | 可交互、可核对的工具桌宠 |
| Phase6 | 集成与V1交付 | Phase5阶段验收 | 普通玩家可启动、配置、维护、迁移 |
| Phase7（可选） | 沉浸体验与视觉精修 | V1稳定，具体体验问题已选定 | 既有功能更顺手、更协调 |
| Phase8（可选） | 新素材与羁绊表达 | 对应资源到齐或回顾需求明确 | 新内容可切换、可追溯、不过度演绎 |
| Phase9（可选） | 长期使用与维护 | 有持续使用反馈和可复现问题 | 长时间运行和人工维护更稳妥 |

7—9可按需要调整顺序，不为等素材阻塞已有版本。影响正常使用、资料可靠性或现有承诺的缺陷随时修复，不要等到后续阶段才处理。

## Phase7：沉浸体验与视觉精修

目标是让已完成能力更自然、更易用，保持记忆大厅和角色在场感，不把主画面改成普通聊天客户端。

| 检查点 | 内容 | 验收 |
|---|---|---|
| 7A 体验审阅 | 汇总玩家在大厅、气泡、输入、菜单和长回复中的具体摩擦，做一轮小范围视觉/交互对齐 | 先形成可评审的目标与截图，不直接大面积重做 |
| 7B 统一表现 | 精修字体/间距/对比度、临时面板、淡入淡出、焦点与收起节奏；需要时小幅调整构图 | 可读可点、不挡角色、不丢输入，动作与气泡协调 |
| 7C 角色视听 | 按具体反馈调整Spine高光、3D材质观感、触摸动作过渡、语气/段间停顿 | 与已认可版本对照，保留恢复设置，不擅改源素材 |
| 7D 日常体验回归 | 中文IME、不同字号、边缘气泡、静音/少动效等实际需要 | 修改没有破坏聊天、工具、复听、记忆或文件接口 |

托盘/开机自启等便利功能只有明确需求时作为单独小项评审，默认不自启；关闭窗口是否退出必须清楚，不能让后台行为令人困惑。它们不是本轮V1交付前提。

**不包含：** 更换UI框架、全面重建渲染管线、第二个常驻聊天窗或无依据地重训声音。已认可的日语默认、中文正文、单曲循环与角色关系继续保留。

## Phase8：新素材与羁绊表达

有对应素材时再启动相关项，继续使用已有独立清单和同一角色核心。

| 检查点 | 内容 | 验收 |
|---|---|---|
| 8A 新陪伴空间 | 审核新Spine清单/版本/图集，适配构图、触摸、表情与口型；普通导入接口继续可用 | 新旧空间可切换，失败保留旧空间，同一人物卡与记忆 |
| 8B 新动作与声音参考 | 对明确交付的Blender动作/特殊表情、准确转写的情绪参考逐项检查，再通过Manifest/voice_delivery接入 | 有实际资源和可对照样例，缺失能力明确回退，不假装八情绪全齐 |
| 8C 回顾阅读 | 依据玩家需要增加按时间/主题浏览、来源跳转、长日记阅读与导出便利 | 能看出聊过什么和角色明确表达的变化，仍可追溯原聊天 |
| 8D 内容维护 | 改善音乐/空间/参考/人物卡的添加、重读与错误提示，补资源制作/交接说明 | 普通玩家通过菜单完成操作，后台直接读文件，无需改代码 |

羁绊表达以真实保留对话和角色表达为依据，区分当时内容与现在回望的感想，不生成复杂好感度数值、不虚构经历、不自动改变人物卡。旧MD和玩家批注保留，新规则只作用于明确的新生成/整理操作。

新资源是**同一个角色的表现扩展**，不是多角色系统或MOD/插件市场。原冻结V7与未提供的Blender稿不自动替换。更强的怒声/哭腔需要真实素材与单独验证，不能只靠标签宣称实现。

## Phase9：长期使用与维护

目标是利用真实使用积累做有针对性的改进，不把项目改造成服务平台。

| 检查点 | 内容 | 验收 |
|---|---|---|
| 9A 长周期观察 | 检查多日使用的内存/显存回落、睡眠恢复、缓存和后台任务边界 | 有可复现样本及前后实测，不凭印象承诺更快 |
| 9B 数据规模与占用 | 在受控大历史样本中检查检索、日记耗时、缓存增长，按需做索引/分页与清理引导 | 保留来源/遗忘规则；清缓存不删聊天，清理范围由玩家明确选择 |
| 9C 版本与维护 | 维护人工更新、数据兼容检查、恢复演练、依赖/资源版本记录与代码审阅说明 | 新旧包和备份对应清楚，不强读高版本库，不静默自动更新 |
| 9D 个别设备适配 | 依据实际目标设备评估启动、推理速度、体积和性能瓶颈 | 单独列已验证配置/限制，不能以一台机器推广到全部硬件 |

优化优先级依据测量：先查重复加载、队列/缓存无上界与没释放的资源，再评估更大的技术变化。模型量化、切换推理后端或CPU语音方案需要独立成本/兼容/听感评估，不作为必做项；原始训练成果和可回退环境保留。

本阶段处理更长使用周期中的问题；崩溃、资料损坏、权限失效等一旦发现就立即修复，不等Phase9启动。

## 各阶段都保持的规则

1. 持久配置、资源清单、版本清单、回顾与维护记录可定位到独立文件；普通玩家使用菜单维护，后端经类型化服务读取/校验，不把读JSON当日常使用门槛。
2. 单角色、单活动模式、同一历史与记忆；AgentPet继续无TTS。模型不能任意执行Shell、改库、改人物卡或自改工具权限。
3. 默认不增加云同步、用户账号、自动更新、插件市场、多Agent、RAG/向量库或Computer Use；未来若要求改变这些边界，另立需求讨论，不藏入维护迭代。
4. 每次先选有限目标，写可检查的验收点，再实施和更新日志/checkpoint；新阶段编号不是无限开发承诺。

**当前路线：按批准的V1完善方案逐项修补与精修，再交付新候选供玩家测试；8/9按后续需求单独启动。**
