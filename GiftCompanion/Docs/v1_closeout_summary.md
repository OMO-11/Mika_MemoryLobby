# Mika Gift V1：设计与实现收尾

2026-11-02，Asia/Shanghai。本文回顾从技术骨架到独立候选交付的完整过程，并记录本次收尾决定。各阶段原始证据保留；“技术验证通过”和“玩家体验验收”分别记录。

## 一、最初要解决的问题

V1的目标是一个Windows单用户陪伴应用：打开后能见到Mika，用中文交流，听到角色声音，回顾过去的聊天，并在重启后继续此前的相处。设计以Mika与老师的原作关系为基础，不预设恋爱、排他承诺或复杂好感度数值。

项目最初规划了陪伴空间与桌宠两种表现。它们共用角色、人物卡、对话、状态和长期记忆，而各自管理Spine/3D、声音、窗口与桌面工具。2026-11-02按用户要求，**默认启动直接进入陪伴空间，桌宠入口暂时关闭**；桌宠代码、资产、工具记录和共享数据库保留。Home仍作为资料维护与故障恢复的入口。

总约束来自项目总宪法：沉浸优先、轻量优先、单角色与单活动模式、一切皆文件、普通玩家可维护。开发采取分阶段审批、逐项实现、保留证据和checkpoint的方式。

## 二、如何把设计分成可完成的阶段

| 阶段 | 解决的问题 | 最终留下的能力 |
|---|---|---|
| 环境与骨架 | 先确定工程、版本、资源与模块边界 | Unity固定6000.3.7f1；工程/原素材/运行环境/玩家资料分开；素材通过清单接入 |
| Phase0 技术链 | 每个关键组件能否在真实Windows运行 | Spine、3D原动画、DeepSeek流式、SQLite落盘、中文/日语TTS与透明窗口分别验证 |
| Phase1 共享核心 | 两种模式是否还是同一个角色 | 唯一AppRoot与CharacterCore；配置、日志、状态持久化；切换取消、保存与恢复 |
| Phase2 长期记忆 | 对话结束后留下什么，如何更正与遗忘 | 原始会话、事实/事件/事项、来源、摘要、FTS5检索和引用失效治理 |
| Phase3 陪伴表现 | 能力如何成为可日常使用的陪伴空间 | 中文输入、临时菜单、字幕、MomoTalk、触摸反馈、音量/字号；修正发布版Alpha表现 |
| Phase3扩展 | 玩家如何管理自己的内容、回望相处 | BGM单曲循环与淡化、音乐导入、Spine空间清单、人物卡编辑、数据库与MD双份日记 |
| Phase4及声音扩展 | 如何自然地说话，同时保留中文交流 | 本地声音进程、分句合成、字幕同步、口型/BGM压低、缓存复听；日语本地化与表达调整 |
| Phase5 桌宠与受控工具 | 桌面形态如何共享人物并执行有限操作 | 透明窗口、气泡、拖动/触摸/热键、13项受控工具、单轮授权与敏感操作确认；本次保留实现、关闭入口 |
| Phase6 独立交付 | 普通玩家能否启动、配置、备份和迁移 | 应用内Key配置、独立Runtime、资料备份/预览恢复、配置修复、脱敏诊断、版本和文件清单 |
| V1完善 A—F | 如何把已有能力收拾得更可靠、更顺手 | 配置确认修复、先看文字、上一版恢复、空间预估、日记阅读位置、显示设置和布局修正 |
| 本次收尾 | 统一当前使用入口并整理成果 | 直接进入陪伴空间，暂时关闭桌宠入口，记录V1整体设计、实现、交付与后续边界 |

各阶段有意先验证依赖，再实现产品流程。例如先确认真实TTS能返回声音，再做队列和复听；先做数据库与来源，再让日记回顾历史。缺少新素材时保留接口与合理回退，不为凑功能虚构新动作或情绪素材。

## 三、核心架构如何支撑连续相处

主流程是：Bootstrap创建唯一AppRoot，载入独立配置、执行待恢复事务、打开SQLite、恢复状态，随后进入活动场景。当前默认场景为Companion。

界面把输入交给CharacterCore；Core组织人物设定、短期状态、允许使用的历史和长期记忆，再调用DeepSeek。回复完成后事务保存原文、展示正文和角色状态，后台记忆任务再进行来源受限的整理。UI不直接调用模型接口或改数据库。

切换、重试、发新消息和退出都必须考虑取消：旧请求先收尾，旧轮迟到文本或音频不能覆盖新轮；后台记忆整理让位于前台；备份维护先暂停角色、等待后台释放、停止声音并保存状态。唯一Core让这些行为共享同一组边界。

实现采用Unity/C#、uGUI/TMP、spine-unity、Generic 3D动画、HTTP/SSE和SQLite/FTS5，没有为V1引入大型Agent编排框架、向量库或插件平台。

## 四、中文交流与日语声音如何协作

实际链路为：

1. 老师输入中文，主LLM生成中文正文。
2. 中文正文保存为聊天原文/正文投影，继续用于前端与记忆。
3. 需要日语朗读时，后台较低成本的本地化LLM将分句改写成符合Mika语气的日语；这一步仍需联网，不是离线翻译模型。
4. 本地GPT-SoVITS使用日语模型和参考音频合成，队列按顺序播放，中文字幕随实际朗读段落显示。
5. 发声时驱动口型并平滑压低BGM，段间留出呼吸；结束后恢复玩家原音量和静音状态。

默认日语、中文正文；中文音色保留可选。表达通过本地化语气、参考素材、语速和停顿配合，覆盖活泼、害羞、恼火、伤心、犹豫和平静等预期；有标签不代表每一种都拥有独立录音或Spine表情，缺失能力明确回退。

声音准备期间文字仍可用。点击“先看文字”只停止本轮声音，继续同一次中文回复；下一轮恢复声音偏好。完整缓存可在MomoTalk复听，缓存缺失不自动补合成。模型子进程独立管理，不继承DeepSeek Key，退出时只停止程序自己启动的服务。

## 五、记忆、日记与人物卡各自承担什么

原始聊天记录是历史依据，长期记忆是带来源的可检索整理，人物卡是玩家主动维护的性格和关系设定，日记是角色口吻的叙事回顾。它们互相协作，但不能相互冒充。

用户纠错或遗忘后，相关事实、摘要、检索引用与日记需要失效或重建，不能从派生内容绕回已排除的信息。原始聊天保留与“不再用于记忆”分别处理；旧备份可能包含更早状态，恢复预览明确说明时间回溯。

日记由玩家主动选择生成，整理从相识到现在的已保留对话，说明聊过的话题、角色当时明确表达的感受以及现在回望的感想。没有证据的影响不编造，日记也不自动改写人物卡。输出自然段和适量颜文字，分别保存到数据库和MD；普通打开不覆盖玩家已有批注。

同一陪伴场景会话中，日记按篇目保存阅读位置；新篇或失效篇不套用旧位置。时间线、主题筛选、来源跳转和增量总结留待后续按需设计。

## 六、“一切皆文件”如何落地

玩家通过中文菜单操作，后端校验和保存独立文件；数据库承担结构化共享历史与索引，MD承担可读回顾和说明。普通玩家不需要把编辑JSON当作日常操作。

| 文件或位置 | 用途 |
|---|---|
| Config/app_entry.json | 本次新增：启动模式与桌宠入口开关，默认companion/false |
| Config/settings.json | 字幕、音量、默认语音语言等日常偏好 |
| Config/character_card.json | 人物设定、称呼与关系边界 |
| Config/bgm_playlist.json | 音乐路径、当前歌曲、单曲循环和淡化参数 |
| Config/companion_spaces.json、Content/ | 空间目录、玩家导入音乐与Spine资源 |
| Config/voice_runtime.json、voice_delivery.json、speech_localization.json | 声音运行、参考/表达和日语本地化规则 |
| Config/diary_policy.json、companion_display.json | 日记整理规则、画面和阅读参数 |
| memory.db | 共享会话、状态、记忆来源、日记与音频/工具索引；当前schema v10 |
| Diary/、AudioCache/ | 可读日记与历史复听文件 |
| Backups/、RestorePoints/、ConfigRecovery/ | 压缩快照、恢复前原资料副本、单项配置原件 |
| Secrets/ | 当前Windows账户加密Key，排除于普通配置、备份和发布包 |
| Logs/、Diagnostics/、Release/ | 脱敏状态/耗时、故障信息和发布版本/哈希清单 |

本次入口文件默认由后端生成，不迁移或清空记忆。临时关闭是可逆的：维护者以后可将PetEntryEnabled设回true并重启；StartupMode可选companion/home。普通运行仍保持关闭，损坏配置回退到直接陪伴与关闭桌宠。

## 七、如何让资料与分发可维护

资源导入先验证格式与依赖，再保存清单；无效资源保留原可用内容。配置使用原子保存并保留上一版；重置前保留和校验主文件、上一版、待写副本。切换项目会取消旧确认，避免显示选择与实际操作不一致。

备份通过SQLite原生Backup取得一致数据，包含WAL提交内容，再生成有路径、尺寸和SHA256的快照。恢复先校验、预览、检查空间，确认后保存当前恢复点；下次启动在开库前应用事务，失败回滚，Key与安装Runtime不替换。曾实际遇到加密资料目录拒绝重命名，最终改为完整复制、落盘和校验后再替换，而不是只依赖理想环境测试。

Windows独立目录随包提供一份双语运行环境与许可证；玩家不必安装Unity、Python或Blender。缓存和临时配置写入玩家资料目录。原素材、训练成果、旧构建和旧验收记录保留，避免把新版本结果覆盖成旧版本已通过。

## 八、验证如何贯穿实现

验证分三层：纯逻辑检查数据规则，场景检查取消/交互/共享生命周期，独立Windows EXE检查真实窗口、文件系统、模型进程与关闭重启。真实接口、合成样本和玩家听感分别标注；测试只使用隔离Validation资料，不用正式私人聊天作为开发样本。

历史证据包括Phase0真实联网与双语合成、Phase2跨模式记忆/更正/遗忘、Phase3发布渲染修复、Phase4声音队列/缓存、Phase5工具授权，以及Phase6独立迁移与恢复。V1完善版在2026-10-23通过164项逻辑、38项场景、42项独立检查；这些数字属于该候选，不直接算作本次新二进制已通过。**本次入口修改的实际结果单独写入v1_closeout_checkpoint.md和Validation/V1Closeout。**

自动通过不能代替主观音色、人物口吻、长期相处和所有屏幕条件。曾出现自动检查通过但显示标签未绘制的问题，最终通过人工截图发现并补实际字符可见性检查；这也是保留视觉复核的原因。

本次入口收尾的逻辑165/165、场景39/39和新独立EXE入口10项检查已通过，包含默认直达、桌宠按钮隐藏、关闭状态的路由拒绝、维护入口仍在、同一Core及正常保存退出。测试关闭语音以隔离入口问题，语音听感与约92秒预热仍沿用前述历史结果。本轮不是重新验收全部外部接口或所有设备。

## 九、V1收尾后的实际边界

V1已经具备陪伴空间、中文对话、双语声音、历史复听、来源受限记忆、手动相处回顾、内容维护和独立备份恢复的基础闭环。桌宠与有限工具有历史实现和证据，本次按用户选择暂不开放。

本地语音环境仍是体积和冷启动的主要成本。最近完善版本机日语首次预热约92秒、完整目录约8.89GiB；这不是所有设备或全对话首音的保证。本次入口修改不等于模型提速，也不改变已认可音色。

长期稳定性、其他硬件、多屏/全部DPI、睡眠恢复，以及真实Key保存重启完整玩家流程仍保留待反馈状态。新Spine素材、进一步动作/表情、日记时间线和完整占用管理属于后续可选工作；本次不自动启动Phase8/9。

收尾的交接重点是：保留清晰的当前入口、能够复核的设计和技术证据、可恢复的资料以及明确的后续边界。后续从实际体验问题继续，不必重新搭建整个V1。
