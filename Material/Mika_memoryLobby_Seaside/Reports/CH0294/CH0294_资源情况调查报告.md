# CH0294_home Spine 资源情况调查报告

调查日期：2026-10-17（Asia/Shanghai）  
调查方式：源文件校验、PNG 解码、图集边界检查、Unity MCP 实际加载、逐动画采样、Unity GPU 预览渲染。

## 1. 结论

**CH0294_home 的骨骼、图集和贴图完整，能够在当前 Unity 6 + Spine 4.2.120 环境解析、生成网格并渲染。当前 Unity 场景和材质配置仍有问题，需要调整后才能作为正常大厅展示。**

- 六个源文件均与交付清单和校验和一致，Unity 中的六份导入文件也与源文件逐字节一致。
- 441 根骨骼、215 个插槽、264 个附件、257 个图集区域全部加载，缺失区域为 0。
- 全部 31 个动画按 30 Hz 单次采样，共 12,975 帧，骨骼矩阵与附件世界顶点均未出现 NaN / Infinity。
- Unity 已实际生成 8 张验证帧；Idle 的不同时间、Idle 与分层 Talk 均有像素变化。
- 导入材质存在 **Straight Alpha 输入未启用**的问题。当前配置渲染有明显白边、白块和过亮；仅在临时材质副本启用该设置后，异常明显消失。
- 当前 `New SkeletonGraphic` 没有 Canvas 祖先，并且多 CanvasRenderer 未启用；这会阻碍 UI 方式的正常显示。
- 资源含海边背景和光效插槽，但不包含完整音频、游戏端镜头与播放逻辑，也没有可编辑的 `.spine` 工程。

本结论表示“骨架和动画可用，导入配置待整理”，不代表原游戏画面、音频与交互已经完整复现。

### A/M 应按时间线职责理解

原包 `README_zh.md` 将 A/M 解释为女声/男声变体，并称差异只在口型与配音事件。**本次实际解析的时间线并不支持这一解释。**

- `Talk_01_A`、`Talk_01_A_CN` 各包含 13 条 AttachmentTimeline，没有骨骼动作或事件时间线。
- `Talk_01_M`、`Talk_01_M_CN` 各包含 98 条时间线，覆盖平移、缩放、旋转、Physics mix 和事件。
- 其余 Talk 的 A 组也以附件切换为主，M 组包含动作与事件。只播放 A 组时，骨骼没有移动并不表示动画损坏，表情或口型可以通过附件切换变化。

适合后续接入验证的分层方式是：底层循环 `Idle_01`，上层播放对应 M 动作轨，再叠加对应 A 附件轨。此次已经用 `Idle_01 + Talk_01_M_CN + Talk_01_A_CN` 生成实际渲染帧，并确认它与单独 Idle 的结果不同。这是经验证的组合示例，尚未覆盖所有组合的混合过渡与原游戏调度规则。

该资源具备待机、入场、固定对话表演、闭眼、看向和抚摸反馈素材。没有明确命名的 Thinking、Listening 或 Working 动画。用于 AI 陪伴时，需要自行定义状态映射、循环与退出逻辑，固定剧情口型也不能直接等同于任意 TTS 的实时口型。

## 7. Unity 实测结果

### 7.1 加载与逐帧采样

使用 MCP `execute_code` 在 Unity Editor 内运行 `ProbeUnity.cs.txt`：

1. 加载项目现有 SkeletonDataAsset，确认返回有效 SkeletonData。
2. 遍历皮肤附件、图集页、材质和贴图配置。
3. 为每个动画创建独立 Skeleton / AnimationState，按 30 Hz 从起点运行至结束后约一帧。
4. 每帧检查所有骨骼的 2×2 矩阵与世界坐标，并计算附件世界顶点，检查 NaN / Infinity。
5. 记录事件、时间线类型与骨骼是否产生变化。

结果：31/31 动画通过，共 12,975 帧；缺失区域 0。该测试能证明实际数据可解析且所采样姿态数值有效，不等于所有动画每一帧的美术效果都经过人工审阅。

## 8. 当前问题与处理建议

| 优先级 | 发现 | 证据与建议 |
| --- | --- | --- |
| 高 | 原材质使用 PMA 混合，但没有将 straight-alpha 纹理输入转换 | 四份材质均为 Spine/Skeleton，`_STRAIGHT_ALPHA_INPUT` 未启用。临时副本启用 `Straight Alpha Texture` 后白边/白块明显消失。建议四页材质统一启用直通 Alpha 输入并检查 UI 对应材质。不要仅凭 atlas 未声明 pma 就认为当前材质已自动适配。 |
| 高 | 当前 SkeletonGraphic 没有 Canvas 祖先 | Hierarchy 中它是根对象。使用 UI 路径时应放入 Canvas；世界空间大厅则可采用 SkeletonAnimation + 相机，本次 GPU 测试已经验证该路径。 |
| 高 | 四页图集，但 SkeletonGraphic 的 Multiple CanvasRenderers 为 false | 本地 SkeletonGraphic 实现明确要求多纹理使用该选项；使用 UI 路径时应启用，并检查子 CanvasRenderer 与 UI 材质。 |
| 中 | 画幅没有完整背景覆盖 | 全范围和示例 16:9 取景可见外沿/空隙。后续需要镜头裁切、缩放、位置和必要的补底，不能直接套用 setup 范围。 |
| 中 | A/M 文档解释有误导 | 按实际时间线组织附件轨、动作轨与事件，避免以男女声标签选出单独的一条轨道。 |
| 中 | 声音资源与播放逻辑未齐备 | 事件有引用，但对应音频当前未找到；需要补充并处理 Sound/语音/Talk 的触发关系。 |
| 低 | 资源存放在 Assets/New Folder | 功能接入前整理到明确的 CH0294 目录，保留现有 meta/GUID 引用关系。 |
| 低 | 纹理内存与 Unity 6 弃用警告 | 当前贴图为未压缩 RGBA32、无 mipmap；先确认画质再决定压缩/Read-Write 设置，后续处理 Editor API 弃用。 |

源 PNG 全解码分析发现大量 `RGB > Alpha` 的半透明像素及 Alpha=0 但 RGB 非零的像素，支持它们是直通 Alpha 输入的判断；单纯当作预乘纹理使用会把原本透明区的颜色加进画面。临时材质对比进一步验证了这一原因。

四页 RGBA32 的单份像素数据共 **48 MiB**。Unity Profiler API 对四份 Texture 对象报告合计约 **96 MiB**；这个数包含 Unity 对象的运行时内存口径，不能直接解释为纯显存。当前 sRGB 标记为 false，最终色彩空间仍需要对照目标画面验证，本次未调整或认定它必然错误。

本次仅调查并进行临时配置验证，以上生产配置调整尚未写入原项目。
