## 2. 视角对齐

原 GIF 的画幅约为 1.53:1，而 Unity 截图接近 16:9。旧适配逻辑按顶部进行 cover 裁切，宽屏会缩小纵向视野，导致下方身体被裁掉更多。

现在所有画幅保持与参考 GIF 相同的纵向视野：20.92 个骨架单位。横屏围绕参考画幅的水平中心扩展，窄屏仍向角色焦点裁切；角色本身不拉伸。

为使新增两侧空间继续由星空和海面覆盖，只在生成网格时调整 `BG_*` 背景插槽的横向顶点，并保留少量边缘余量。没有缩放 `BG` 骨骼节点：本资源的 BG 节点实际上也包含角色骨骼，直接缩放会连带改变角色比例。

海浪贴片本身有倾斜的透明边缘。宽屏新增区域可能在角色右侧露出少量缝隙，因此额外使用原图集 `CH0294_home_3.png` 中完全不透明的海面内部区域，在下半画幅垫底。这是同一套海面素材的延展，未绘制新图、未替换动态海浪；在原参考比例下该垫底关闭。

跨画幅验证：

| 输出 | 纵向视野 | 额头归一化 Y | 主角色页顶点差异 |
| --- | ---: | ---: | ---: |
| 1652 × 1080 | 20.92 | 0.783518 | 0 |
| 1920 × 1080 | 20.92 | 0.783518 | 0 |
| 2520 × 1080 | 20.92 | 0.783518 | 0 |
| 1080 × 1920 | 20.92 | 0.783518 | 0 |

Y 按 Unity 屏幕坐标从下向上计算。不同输出使用同一个动画时刻；角色页网格顶点数组逐点一致，因此既对齐了纵向取景，也确认没有将角色横向拉宽。背景的横向分布允许随画幅变化。

## 4. 额头到头顶的抚摸

### 判定

使用随 `Head_Rot` 骨骼移动和旋转的椭圆区域，在头部局部坐标中定义，覆盖额头和头顶，不包含眼睛、脸颊及下巴。它会随角色姿态、窗口尺寸和画幅变化进行屏幕坐标换算，不是固定在屏幕上的按钮。

已检查：中心和额头能命中，脸颊、头顶上方及侧面外部不会命中。

### 插入、保持与结束

```text
额头区域按下
→ Idle 底层继续运行
→ Pat_01_M + Pat_01_A 混入
→ 原生 0.333 秒反馈播放后，保持最后姿态
→ 松开 / 移出判定区 / 窗口失焦
→ PatEnd_01_M + PatEnd_01_A
→ 上层轨道混出，回到持续运行的 Idle
```

- 初次插入使用 Spine 的 empty animation → queued animation 模式，真正从底层姿态混入；仅在空轨道上设置 MixDuration 不足以实现这一点。
- 不循环短暂的 0.333 秒反馈，避免长按时频繁回到起点。
- 最短反馈为 0.35 秒，快速点击也不会刚开始就被结束动作截断。
- 移出有 0.14 秒宽限，轻微越界不会立刻切换；按住拖回时可以继续反馈。
- 结束混合和轨道清理完成后恢复待机；抚摸过程中不调用 SetToSetupPose，不重启 Idle。
- 鼠标通过项目已有的 Input System 读取，同时实现触摸输入路径。此次实际注入验证的是鼠标设备；没有进行真机触摸测试。

专项连续性采样中，按下与松开边界的头部单帧位移约为 0.002 个骨架单位；完整抚摸与结束段的最大头部单帧位移约为 0.014。Idle 轨道时间从约 0.5 秒继续前进到 4.5 秒，未被重置。这是该测试姿态的结果，不代表对所有鼠标轨迹作数值保证。

## 5. 待机小表情

新增三个低幅度表演：

| 表演 | 实现与幅度 |
| --- | --- |
| 看向玩家 | 轻微眼神偏移，头部约 0.75° 的倾斜 |
| 闭眼微笑 | 原生 Eye_Close_01 的闭眼姿态，与约 1.1° 的轻微歪头组合，保留原有微笑嘴形 |
| 看向别处思考 | 小幅视线偏移，配合反方向约 1.25° 的头部倾斜 |

每段持续约 2.5–4 秒，再平滑退出；段落之间休息约 8–13 秒。原有呼吸、发丝和海浪待机动画持续运行。入场、抚摸和对话具有优先权，自动表情会淡出让位。

头部和眼神的程序偏移在每次 Spine 应用动画前先移除，再叠加当帧的新值，避免长期累计歪头。闭眼使用独立轨道，退出时清除，防止闭眼残留。

这些是基于原生闭眼动作和现有骨骼的小幅运行时表演，不是新增的原画或重新制作的完整剧情动画。

## 6. 验证与边界

- 13 项功能检查、13,711 个定步长采样帧通过，骨骼数值均有效。
- 覆盖快速点击、长按、移出宽限、重新进入、失焦结束、入场期间禁止抚摸，以及对话回归检查。
- 自动表情调度运行 140 秒的模拟时间，三种表情均出现，并确认能清理闭眼轨道。
- 创建临时 Input System 鼠标设备注入按下和松开事件，确认真实输入读取路径能进入反馈、进入结束并返回待机；临时设备已移除。
- 新入场与互动两段连续渲染共 304 帧，画幅覆盖检查通过；另有 20 张静态画幅/表演截图。
- 跨画幅主角色页顶点数组一致；背景顶点映射有计数校验，防止误改角色网格。
- 原始六个 skel/atlas/PNG 文件 SHA-256 与初始调查一致。

验证过程中，离屏截图脚本曾在恢复编辑器后又手动渲染无 RenderTexture 的相机，触发编辑器 UI RenderPass 尺寸错误。该清理调用已移除，诊断记录保留在 `offscreen_cleanup_errors.json`。重新进入 Play Mode、运行功能检查后未发现新增 Error；没有通过修改项目渲染管线来规避这个采集问题。

本次没有打包 Windows 程序、进行 FPS 基准或手机触摸真机测试。GIF 为 Unity 实际渲染帧转换，颜色受 GIF 调色板限制，画质核对应以 PNG 和 Unity 为准。
