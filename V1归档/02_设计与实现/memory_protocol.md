# 记忆协议与阶段边界

两个身体共用一个数据库、MemoryService 和 Retriever。Phase 2A—2E 已验收；Phase 3 将同一服务接入正式 Companion UI，详见 `phase3_status.md`。Phase 0 独立 SQLite / FTS5 验证库不作为第二套角色记忆。

正式 `memory.db` 目前支持 schema v8：原始对话、正文 / 表现投影、事实 / 事件 / 事项、FTS5、摘要覆盖 / 来源 / 版本、消息及具体记忆的回复引用，以及 relationship_journals / journal_sources。audio_records 留到 Phase 4。升级有原生备份与事务；自动验收只迁移隔离库，用户正式库将在普通启动时按版本升级。

Phase 3F 的相处日记由玩家手动触发，分批回顾首次使用至今两个模式全部已完成且未排除的聊天。滚动摘要只用于这次回顾，未写入检索事实。来源水位、记忆版本、人物卡哈希共同决定复用；生成中版本变更拒绝提交，取消不保存半篇。角色感受只依据原文中明确表达，不推断真实心理或新增共同经历。日记与自动会话摘要是独立用途。

日记数据库先保存正文、全部消息来源和待导出状态，再在同一数据库串行队列内写 Markdown，避免遗忘与导出交错。导出失败可重试；删除可读副本后从数据库重建，已有成功副本普通查看不覆盖。文件名使用 UTC 时间 + ID，展示日期仍用本地时间。记忆更正 / 遗忘保守失效该角色旧日记：正文清空、状态 needs_review、MD 更新为收起说明，不留含旧正文的 .bak。原始聊天按既有审计规则保留；MD 外部编辑不写回数据库，日记不作为新的用户事实或人格。重要手工批注宜另存副本。

用户原文先保存；完整 assistant 原文、正文 / 表现投影、完成状态、Mood、提取 pending 与交互时间共同提交。取消 / 截断保留用户消息状态，不进入完整上下文或提取。提取在共享服务后台执行，写入复用 DatabaseService 单连接串行队列；前台可取消后台，待办保留，失败显式重试。

提取结果严格校验四个数组、字段类型 / 范围、用户消息 ID 和原文证据；assistant 推测不能成为用户事实。事实去重及基础 superseded 历史保留已实现，Open Loop 只按已有候选解决。不能将原文证据校验当作模型语义绝不会误判的承诺。

检索使用 FTS5 unicode61，并对中日文补充单字 / 双字索引词，保留连续中英文中的英文标识符。查询只生成有界的引用词 OR 表达式，不接受原始 FTS 语法。原始 bm25 取负并按候选最大值归一化，recency 为 `exp(-天数/30)`，最终按 `0.60 relevance + 0.25 importance + 0.15 recency` 排序；并列按时间、ID 排序。

PromptBuilder 按宪法顺序取最多 20 条事实、5 条相关事件、5 条事项、6 个完整近期轮次，摘要插槽最多 1,000 字符，总字符上限 12,000；保留真实历史角色，当前输入一次。提取未完成也能通过共享近期上下文衔接模式切换。引用来源与上下文版本随完整回复保存，版本变化拒绝提交过期结果。

摘要已在模式退出 / 累计 10 轮 / 8,000 字符时后台触发，保留覆盖范围及来源，不替代原文。失败可显式重试，取消任务恢复 pending；版本失效的旧摘要拒绝提交，重建只使用允许的原文。

Core 按明确记录 ID / 轮次 ID 遗忘，先取消在途回答，事务内将目标置为 forgotten、移出索引、排除相关原文与引用回复、失效摘要并抑制旧提取。记录引用与消息引用分别保存，同条消息的独立事实可继续回答；原文不物理删除。新的明确陈述可以重新记住，旧任务不能恢复被排除的来源。

Phase 2 的跨模式 / 长期事实 / 重开、纠错 / 遗忘 / 独立事实、无 Key 本地记忆是保留基线。Phase 3 在 MomoTalk 提供“不记住本轮”，设置中按明确记忆记录移除，仍经同一 Core 执行；自然语言对象消歧未扩展。

schema v7 的 `assistant_presentations` 以原 assistant message_id 为主键 / 外键，保存 protocol_version=1、body_text、emotion、action。messages.content 保留完整模型原文，包括首行 META；正文投影是同一次解析结果，不是再次改写。历史、近期上下文、提取和摘要统一通过轮次读取使用投影，消息 ID / 来源 / 记录依赖不变；v6 旧消息没有投影时原样读取，不猜标签、不改原文。v6 升级备份、取消 / 存储失败不提交投影或 Mood 已有测试。

ConversationHistoryService 使用 `(created_at, user message ID)` 倒序游标，默认 30、最多 100 轮，参数绑定并通过同一 SQLite 串行连接执行。可包含失败 / 中断和已遗忘轮次供历史查看，完整上下文仍遵守排除规则；相同时间分页不重复、不漏页。历史服务没有新增另一份聊天存储。当前 Companion META 策略也计入原有 12,000 字符总预算。
