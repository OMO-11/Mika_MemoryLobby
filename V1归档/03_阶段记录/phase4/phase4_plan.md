# Phase 4：正式语音链路与历史复听方案

2026-10-17 制定，用户已批准实施。**已按 4A→4E 完成技术实现与阶段验收，玩家体验待反馈；最新进展见 [phase4_status.md](<phase4_status.md>)**。依据[项目总宪法](<../../02_设计与实现/项目总宪法.md>)第 15—20、44、49—50 节，以及[此前交付](<../phase3plus/phase3plus_delivery.md>)、[文件接口](<../../02_设计与实现/player_content_contracts.md>)和[内置语音运行时](<../../02_设计与实现/voice_runtime.md>)制定。

## 当前结论与目标

用户已审阅日记以外的本轮新增功能，反馈没有特别严重的问题；这些功能记录为已通过本次玩家审阅。日记技术验证已完成，玩家体验仍待确认，不将其标成失败或已验收。未来第二套 Spine 尚未提供，现有接口验收不代表未提供的资源已适配。

下一轮让陪伴空间从文字对话进入真正的语音对话：边生成边分句朗读，能够立即停止旧声音，语音带动口型与音乐压低，历史可以复听已有缓存。唯一 CharacterCore / State / Memory、原文与正文投影、人物卡和资料文件继续沿用。主画面保持大厅构图，操作收进临时菜单。

## 实施前基线

- Unity 6000.3.7f1，现有 Built-in / Gamma / D3D11 和 spine-unity 4.2；不为语音更换渲染或 UI 框架。
- 正式对话已有正文增量、请求代次、取消与消息完整提交规则；现有 Speaking 是文字表现，不能把它当作正在播放声音的证据。
- GPT-SoVITS 已内置在 Assets 外的 `Runtime/GPT-SoVITS`，含中日文模型、自带 Python 与推理依赖，两种语言的本机 HTTP 技术链均曾验证。默认中文，日文独立配置保留，不要求玩家重新安装 Python 或重新整理模型。
- 既有首请求实测约 8—11 秒，仅作历史参考；不是正式分句播放延迟承诺。本轮分别记录启动、首段生成、首次播放及后续段间隔。
- BGM 已有玩家歌单、手动切歌、单曲循环和淡化；新增 Ducking 只影响临时混音，不改写玩家音量或自动切歌。
- 当前数据库 schema v8，尚无正式 `audio_records`。新增缓存索引走已有迁移 / 备份机制，实际新版本号实施时统一确定。

## 待验收项：长期回顾（日记）

由玩家自行选择何时生成，独立于 4A 的开发，不自动读取正式聊天为玩家生成回顾。

- 检查是否能回望相识至今的主要话题，以及角色曾表达的感受与关系变化；不只总结当天或最近几轮。
- 检查文风与事实：不编造共同经历，不把角色当时的推测当作老师的表态，区分当时表达与此刻回看的感想。
- 检查菜单阅读、Markdown 输出和重启后查看是否便于日常使用。有具体反馈再调整，不因尚未阅读而重写现有功能。

## 按顺序执行的任务

### 4A：配置文件与运行时生命周期

1. 增加独立语音配置文件，拟定为用户资料下 `Config/voice_runtime.json`；用相对路径引用运行时及既有 `voice.json` / `voice-ja.json`，不复制模型参数形成第二套真相。配置包含默认语音、启动 / 就绪 / 请求超时与队列边界；开关、音量使用现有玩家设置服务。
2. 实现 VoiceRuntimeManager：仅 Companion 按需启动项目自带 Python，等待真实接口就绪；Home / AgentPet 不启动语音，退出 Companion 清理播放、请求和自有进程。
3. 复用现有脚本的本机绑定、进程身份核对、离线模型加载与日志经验。端口被其他程序占用时不接管、不终止对方，也不将“端口打开”视作本项目服务就绪。
4. 启动慢、缺文件、显存不足或服务退出时继续文字对话；设置中提供语音开关、音量和“重试语音”。技术原因写诊断文件，主画面只给自然简短反馈。

**验收：** 从普通启动器进入大厅能自动就绪；反复进入 / 离开不重复开服务、不残留自有进程；无法启动时文字链完整可用，普通玩家无需终端操作。

### 4B：流式断句、单并发推理与音频播放

1. SpeechSegmenter 只接收已解析正文，按完整语义与标点增量切分，设最小段、目标长度、最长段和末尾冲刷规则；清理朗读用 Markdown / 控制字符，不改变数据库原文或展示正文。
2. 建立 TTS 请求队列与生成音频队列，单次仅一个实际推理；第一段 WAV 就绪就播放，播放第 N 段时允许生成第 N+1 段，不等待全文结束。第一版不引入低层流式解码器。
3. 接入请求代次和取消：停止旧音频、清空旧队列，迟到结果不得进入新轮。取消 HTTP 不代表 GPU 推理已经停止；未确认旧推理结束前不并发启动新推理，超时后走有界恢复流程。
4. 控制等待队列、临时 WAV 与 AudioClip 占用；HTTP / 解码失败切回文字，不伪造朗读成功，也不把半篇回复保存为完整 assistant 消息。

**验收：** 长回复首段开始朗读时后续正文仍能生成；次序稳定，无 META 朗读、丢尾句、重句或双重推理。用可控流验证时序，并用真实 DeepSeek / GPT-SoVITS 验证实际效果。

### 4C：打断、字幕 / 口型与 BGM Ducking

1. 新消息立即停止旧声音；补齐主动停止、连续快速发送、返回 Home、退出、切换空间与失败清理。普通菜单开关不暗中丢弃当前对话，界面接管和播放状态分别管理。
2. 语音可用时按实际播放段推进字幕与 Speaking；纯文字时保留现有正文显示与状态回退。完成 LLM 回复与完成朗读是两个事件，不能在全文生成完后提前结束口型。
3. 复用已有 PCM 音量包络组件，按实际语音播放位置驱动已适配大厅的嘴部；暂停 / 停止 / 静音及时闭嘴。BGM 不参与口型，未适配的新空间保持安全回退。
4. BGM 在角色真正发声时平滑降至玩家设定音量的约 45—60%，结束 / 打断 / 失败后恢复；跨短句避免反复抽动。压低系数与玩家音量分开，保留静音、手动淡化与单曲循环语义。

**验收：** 快速打断没有旧声音或旧回调串入；口型来自语音而非字幕或 BGM；音量恢复平滑，静音不会被自动解除，玩家原音量不被保存成压低后的值。

### 4D：文件缓存、数据库索引与 MomoTalk 复听

1. WAV 存用户资料 `AudioCache/`，数据库 `audio_records` 保存 message_id、segment_index、相对路径、时长和创建时间，并记录必要的语音配置版本关联。缓存文件可直接定位，界面经服务访问，不直接读 SQLite。
2. 成功提交的 assistant 消息才关联正式缓存；取消 / 失败轮次的临时音频不冒充完整历史。处理文件与数据库无法同事务提交时的中断恢复、缺失文件及孤立临时文件。
3. MomoTalk 只播放本地已有片段；旧文字记录、缺失或不完整缓存明确显示不可完整复听，不自动补调 GPT-SoVITS。无 DeepSeek Key、语音服务未启动时仍可复听完整缓存。
4. 实时对话优先于历史复听；两者都使用同一播放仲裁与 Ducking，不重叠朗读。提供缓存占用查看与清理入口，清理音频不删除聊天 / 记忆，沿用既有遗忘与历史保留规则。

**验收：** 重启仍能按原顺序复听；删除缓存后按钮状态正确且没有后台重生成；数据库升级有备份，音频索引不改变原文、人物卡或记忆来源。

### 4E：发布版回归、试听与交接

1. 针对新断句 / 队列 / 取消 / 缓存迁移做必要自动验证，回归既有对话、文件资料、空间切换和共享记忆。真实服务测试用隔离资料，不调用正式历史生成测试内容。
2. 发布版验证冷启动、后续轮次、长回复、连续打断、端口占用、运行时缺失 / 崩溃、缓存缺失、无 Key 复听与正常退出，记录延迟、队列上界和清理结果。
3. 输出独立 Phase4 开发构建；沿用现有约 8.66 GiB Runtime，开发验证避免重复复制，路径通过配置解析。最终跨机安装与进一步体积优化留到 Phase6。
4. 由玩家试听声音相似度、语气、音量、段间停顿和字幕节奏。技术通过与主观听感分别记录；默认中文正式闭环优先，日文模型不混入中文参考音频或转写。
5. 各段实时更新开发日志与 checkpoints，最后交付启动入口、普通玩家语音说明、文件接口、维护报告和阶段状态。

**验收：** 长回复能够边生成边说、可打断、可离线复听，语音失败仍可文字陪伴；已有音乐 / 空间 / 人物卡功能保持可用，退出没有任务遗留的语音进程。
